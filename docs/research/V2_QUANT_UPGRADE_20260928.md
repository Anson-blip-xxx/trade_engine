# V2 量化候选改造：实现、验收与启用边界

日期：2026-09-28，展示时区 Asia/Shanghai（UTC+8）。

依据：`QUANT_TRADING_VAULT_REVIEW_20260928.md`；实现工作区为
`/home/ubuntu/.opencode/trade/trading_engine-v2`，基线 `12c1ed3`。
本报告记录本轮工程实现，不代表研究路线图的所有收益、影子运行和交易所验收阶段已完成。

## 1. 当前结论

- P1/P2 的五类入场规则和公共指标、市场状态、ATR 退出、统一风险定仓已接入 V2 工作区。
- 新模块没有自己的交易所下单器；仍经过现有账户、保证金、幂等意图、交易所保护和结算链路。
- 新策略默认 OFF，进程能力与账户开仓开关均默认关闭；本轮没有发布、重启服务或向交易所提交新策略订单。
- 离线协议集成测试使用真实 PostgreSQL 事务和 V2 执行器，但交易所响应由假服务提供。不能称为币安真实成交验收。
- 现有短期归档回放结果不支持启用这些默认策略；未获得样本外盈利证据。
- 没有复制或执行第三方策略脚本；按通用数学规则独立实现。没有因此宣称第三方仓库全部代码已取得商业使用许可。

## 2. 新链路与模块分工

```text
共享 Binance 永续行情（仍只有原来的一套采集与配额）
  → ClickHouse 已收盘 1m 归档 / 可重建 Redis 上下文
  → UTC bar 边界聚合真实周期 → quant-closed-bars-v1
  → quant-candidates-v1 注册表 / 参数校验 / warm-up / 计算预算
  → PostgreSQL 不可变观察证据
  → SHADOW：仅记录，不发布订单候选
  → CANDIDATE：source=quant，固定确认时刻和到期时间
  → 独立归档复算 + 当前币种资格 + TV/S3 同机会证据与去重
  → S6/S8 准入 / 同一账户资金与风险引擎 / 持久化意图
  → 提交前开关和现价复核 → 原有执行、成交核对、原生保护
  → 既有退出 + 可选 ATR 追踪退出 → 减仓/平仓成交核对
  → 费用、资金流水、结算 → 版本隔离的归因与首页漏斗
```

S6/S8 是多空执行生命周期，不是五类插件的策略身份。插件身份、参数摘要、指标版本、周期和确认 bar 单独保存，不能混成同一策略历史。

| 组成 | 主要文件 | 本轮行为 |
| --- | --- | --- |
| 标准数学 | `v2_core/quant_indicators.py` | Decimal、真实周期、Wilder ATR/RSI/DMI/ADX、CI、EMA；拒绝缺失/乱序/未来 bar |
| 插件注册表 | `v2_core/quant_registry.py` | Donchian+RVOL、BB/KC squeeze、ATR 通道、Supertrend、RANGE-only 滚动 VWAP 回归 |
| 研究与证据 | `services/v2_quant_research.py` | PG CAS 配置与观察、幂等发布、ClickHouse 独立复算校验 |
| 准入 | `services/v2_quant_admission.py` | 标准 ATR 止损、追价上限、冻结规则；复用方向性资金引擎 |
| 运行接线 | `v2_shared_market.py`、`v2_testnet_daemon_entry.py` | 共享采集、受限研究预算、成对 S6/S8 消费者、账户级启停 |
| 退出 | `services/v2_quant_exit.py`、`v2_directional_exit.py` | 冻结入场参数，PG 保存水位，ATR 追踪只收紧，原生硬止损继续存在 |
| 研究回放 | `v2_core/quant_replay.py`、`services/v2_quant_archive_replay.py` | 下一 bar 成交、成本、跳空、不利同 bar 顺序、开放尾仓、不伪造完整历史 |
| 分析与展示 | `directional_outcomes.py`、`v2_performance_reporting.py`、`v2_dashboard.py` | 参数/周期/版本隔离业绩；QUANT 计入收到→处理→意图→成交漏斗 |

旧滚动分钟窗口和旧 ATR/RSI 定义未被重新解释。新特征使用独立版本，不能把历史旧证据标成新指标。
指标使用有限且确定的 warm-up 种子；目前未逐 bar 对齐独立 TradingView 参考样本，不宣称与所有 Pine 内置指标初始化一致。

## 3. 安全与幂等约束

1. 观察身份包含环境、币种、周期、确认时间和配置摘要；策略/指标版本也进入配置摘要。重复投递和中途崩溃重试不会刷新信号寿命。
2. PG 观察正常只允许第一版；读取时拒绝删除或版本变化。业务状态审计由现有 PG 机制保存，Redis 不是真相来源。
3. 下单准入独立从 CH 重建 bar 和指标，不把已写入 PG 的 Redis 来源特征自动当成可信证明。
4. 未注册事件、来源不匹配、证据篡改、历史不足、过期、未上市/非交易合约、陈旧行情均不能授予开仓权限。
5. TV/S3/QUANT 共享同账户/环境、同币种方向的机会锁；QUANT 同来源的相关候选也去重。多个相关指标不是多票独立置信度，不自动提高仓位。
6. 候选分数仅为排序规则，不是胜率。`ATR_TARGET_NOT_FORECAST` 是距离/成本评估假设，不能当预测收益承诺。
7. 最终提交前重读全局/账户启用状态、插件与周期是否仍启用，再使用交易所准备检查的同一份新鲜标记价复核追价和止损方向。旧候选不因配置改变而无限有效。
8. 相同订单回执丢失后先查询成交，不盲目再 POST；原生保护撤单回执丢失后也先查询，不盲目再 DELETE。
9. 原生硬止损不随 ATR 软件追踪被撤换。本轮 ATR 是软件 reduce-only 退出增强，不是交易所原生追踪止损替换方案；进程停止时仍依赖原生硬止损。
10. 全局研究停用不关闭已有仓位的保护/平仓能力。LIVE 候选生产明确拒绝，不存在由测试策略直接打开真实资金交易的默认路径。

新策略复用资金预算和动态配置，不引入本地 JSON/SQLite 业务台账，也不写密钥文件。测试日志、研究报告属于工程产物，不是在线仓位数据。
bar 时间仍按 UTC epoch 边界；UTC+8 用于展示和既有统计日界线，不挪动交易所真实 bar。

目前跨来源合并复用“第一份已持久化可执行决策占用机会”的规则，并不是等待全部来源后做全局最优评分。
相反方向的跨来源候选仍由现有账户/币种槽位及风险约束互斥；同一量化观察内部多空冲突会直接拒绝。
已保存 TV 的同向/反向证据，但尚未证明新的跨来源优先级或投票规则能够提高收益，不能把去重描述为已经完成了这项研究。

## 4. 本轮修复的生命周期缺陷

完整协议测试发现：软件平仓已成交，但交易所没有自动终止原生保护父单时，原链路可永久停在“保护单没有账本敞口”。

新增受限清理仅在以下条件同时成立时允许撤销一张已登记父单：

- 写权限已开启，持有同账户执行锁；
- PG 证据、账户范围、父单身份与最初止损计划完全对应；
- 全部订单状态已确定，账本开仓量等于平仓量且开仓量大于零；
- 同币种没有未确定提交/普通挂单，交易所该币种实际已平；
- 只操作已登记父单，不撤其他币种的保护，也不借此触发开仓。

测试注入“DELETE 已成功但回复丢失”，下一轮通过查询恢复，不会重复撤单。本轮未向实际交易所执行这段清理。

## 5. 配置与操作说明

### 全局研究策略（PG）

`QuantPolicy`：默认 `mode=OFF`；周期 `(5,15)`；插件 `(donchian,squeeze)`；
候选寿命 90 秒；归档读取上限 14,400 分钟；每轮研究预算 2,000 ms。
周期/插件/数值均有白名单及范围约束。参数通过 CAS 更新，不依赖修改 Python 常量。

模式含义：OFF 不研究；SHADOW 记录观察不发布候选；CANDIDATE 发布候选但不等于允许账户开仓。
配置损坏或删除时研究标记 INVALID 并报警，原有共享行情仍继续运行。

只读查看：

```bash
python3 -m services.v2_quant_policy
```

后续经发布验收启用 SHADOW 的操作示例（本轮未执行）：

```bash
python3 -m services.v2_quant_policy --expected-version 0 \
  --set-json '{"mode":"SHADOW","timeframes":[5,15],"plugins":["donchian","squeeze"]}'
```

必须先读出当前版本，不能永远用 0。设置对象是整份研究策略，未指定项回到该版本默认值，非局部 PATCH。

### 账户与进程

- `quant.admission_enabled=false`：账户是否允许新量化候选。
- `quant.trailing_exit_enabled=false`：是否增强量化仓位的 ATR 软件退出。
- `quant.max_chase_atr="1"`：追价距离上限，提交时取当前与冻结配置中更严格的值。
- `quant.base_leverage=2`：基础杠杆，仍受既有自适应杠杆、风险、交易所准备检查约束。
- `V2_ENABLE_QUANT_SIGNALS=false`：进程消费者能力；设 true 必须同时启用 `V2_SHARED_MARKET=true`。

账户配置沿用现有 PolicyStore 的审计/CAS 通道，不包含账号或密钥硬编码。本轮没有新增独立策略控制台；首页增加的是来源和统计展示。

### 发布与回退次序

1. 先发布具备新能力但全局 OFF、账户准入 false 的版本，验证服务依赖、PG 权限与旧流程。
2. 受控环境启用 `V2_ENABLE_QUANT_SIGNALS=true` 接线，但保持账户准入 false，再开启 SHADOW 观察拒绝原因、预算跳过、信号 age、PG/CH 负载；不开新策略订单。现有独立健康检查以该进程能力标志决定是否读取量化研究异常，不能只开全局 SHADOW 却误以为已启用量化告警。
3. 独立数学参考、样本外及资源门槛达到后，才打开 CANDIDATE 和单个测试账户准入，取得实际交易所完整证据。
4. 停止新开仓时先关账户准入，再将全局模式改为 OFF；保留新版本管理已有新策略仓位。
5. 二进制退回旧版前必须处理新 runtime policy 键的兼容迁移和已有新策略仓位；旧版 schema 会拒绝不认识的配置键，不能直接宣称切换旧发布目录即可回滚。

## 8. 性能、QA 磁盘事件与限制

受 QA 并发负载影响时，纯指标/五插件 160 次测量：5m P50/P95/P99 为 7.400/9.559/11.673 ms；
15m 为 10.034/16.624/18.630 ms；60m 为 9.287/14.404/15.276 ms；进程最大 RSS 19,328 KiB。
该数据不含 PG、CH 或网络，不是全市场容量结论。

研究只复用现有归档/共享分钟数据，不额外向 Binance 轮询。
预算是协作式轮次预算：已用完时跳过后续研究并暴露统计；单次 PG/CH 调用仍可能超过预算，不是硬实时抢占。
旧采集成功不会因单个研究模块报错而被标成失败。后续仍需测全币种的完整延迟、覆盖率和 IO。

本轮 QA 曾因旧脚本保留每次 PG 数据目录、叠加并行 QA，占用磁盘触发运行环境 8 GiB 保护阈值，实际行情刷新一度暂停。
没有调低安全阈值。只删除已确认停止的隔离 QA PG 目录，保留日志；它们是可重建测试数据，不是业务/历史行情/账户库。
释放后只读查询确认行情心跳重新更新（一次检查 age 2,673 ms，CURRENT），未重启行情服务。
这属于真实运行影响，不能描述为“测试完全不影响环境”。

QA 脚本现在同工作区串行、启动要求至少 10 GiB 空间、结束停止自有 PG/Redis 并默认回收自有 PG 数据，保留 pytest/服务日志。
`V2_QA_KEEP_DATABASE=1` 仅供显式故障诊断；停止不能确认时保留数据并返回非零，不做盲目删除。
仍应把长期/压力 QA 迁到独立主机或磁盘卷；预检不能保证运行期间别的进程不会消耗磁盘。

容量不能只看计算延迟。以当前 524 个合约、5m+15m 全覆盖为算术例，每天约 201,216 份观察；
合成平盘样本单份 JSON 为 2,656/2,657 字节，仅原始 payload 约 509.72 MiB/天。
这不是实测增长率，尚未包含 JSONB/索引、状态历史、outbox、WAL 和备份，候选/参数改变也会改变大小。
当前没有新增业务证据自动清除规则，不能擅自删掉可追溯数据；全市场多日 SHADOW 前须验收保留周期、归档和空间预算。

### 已实现

- `v2_core/reentry.py`：可配置、纯函数的退出原因约束、回调再启动、新突破路径。
  初始突破延续仅用于部分盈利退出类型；动能失败/紧急退出需要先修复结构；停滞退出还要求波动扩张。
