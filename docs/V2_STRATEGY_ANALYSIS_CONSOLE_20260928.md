## 实现范围

本次把已有账本、决策证据与动态参数接到同一个账户级页面
`/accounts/strategy`。页面选择账户只改变分析/配置目标，不切换交易执行账户。
不会自动放大仓位、启用新策略或开启 LIVE。

### 分析

- 按账户、环境、来源、方向性消费者、策略版本、配置摘要、市场状态，以及量化插件/周期/版本分组。
- 已结算净收益、胜率、平均单笔净收益、利润因子、中位持仓时间；维护单排除。
- 手续费明细独立展示，不能从已扣费净收益再次扣除；未结算不当作零收益。
- 资金定仓解释展示评分分配、交易所可用保证金、单笔保证金、止损风险中实际生效的最小约束。
- 新退出状态可记录标记价采样浮盈/浮亏；不是完整价格路径，采样错误不阻断平仓。
- 旧决策没有解释、旧仓位没有采样时明确标记缺失，不补造历史。

分析窗口为 1/7/14/30/90 天；交易与定仓证据最多各 500 条，消费回执最多
5000 条、分组前 100 项。截断在 API/UI 明示，不能把局部样本解释为全量业绩。
交易统计按最后平仓成交时间归属；未平仓意图以创建时间筛选，只有已结算策略交易进入收益统计。

### 可配置边界

当前 Web 仅开放九项已接线的资金参数：

| 参数 | 含义 |
| --- | --- |
| `capital.pool_fraction` | 总保证金预算比例，上限 0.70 |
| `sizing.pool_fraction` | 定仓资金池比例，必须与总预算相同 |
| `capital.margin_buffer` | 预占保证金缓冲 |
| `sizing.max_margin_fraction` | 单笔保证金上限；5% 是可改参数，不是永远固定规则 |
| `sizing.risk_fraction` | 单笔计划止损风险比例 |
| `portfolio_risk.max_fraction` | 组合计划止损风险比例 |
| `sizing.min_allocation` / `sizing.max_allocation` | 剩余资金池的分配范围 |
| `sizing.cost_buffer_fraction` | 定仓成本缓冲 |

同时检查单笔保证金不大于资金池、单笔风险不大于组合风险、分配最小值不大于最大值。
这些是工程校验边界，不代表所有允许的组合都具有经济合理性。
其余完整参数只读；本期没有把全部策略、杠杆、退出和开关搬到 Web。

总保证金 70% 是使用上限，不是承诺每次把 70% 用完，也不是最大损失保证。
单笔上限提高后，评分分配、波动折扣、止损风险或交易所限制仍可能先约束实际金额。
已持仓亏损会改变余额/可用保证金，滑点和跳空也可能突破计划止损；不能据此承诺不会爆仓。

### 预览、发布与恢复

1. 展示当前版本和参数；编辑后必须重新预览。
2. 预览包括固定 1000 USDT / 3 倍 / 不同止损距离的算术情景，以及近 14 天最新
   100 份决策的冻结证据定仓重算。旧算式无法精确复现时跳过并计数。
3. 历史预览仅改变选定参数，冻结当时行情、杠杆、止损与账户事实。它不是组合回测，
   不重建预占/后续成交/退出，不按仓位倍数放大历史收益；不提供假设盈利数字。
4. 预览五分钟有效。发布需要变更原因、版本匹配和预览摘要；账户/草稿变化使预览失效。
5. PostgreSQL 受限函数与最终 Testnet 发单共用账户锁。版本 CAS、历史、审计事件原子提交。
   同一请求响应丢失可幂等重试；已提交请求超过预览期限仍返回原结果。
6. 恢复创建新版本，只恢复这九项字段，不恢复交易开关、资金锚点或旧仓位退出参数。
7. 保存只影响执行器后续读取参数的环节，不代表已经产生订单。

新函数合并原始配置中的已选字段，保留其余原始键，不把新版本全部默认参数写入旧执行器。
这样避免旧运行版本因不认识量化新增字段而拒绝整份配置。

## 安全与部署边界

- 复用现有 HTTPS owner 鉴权、可信回环代理身份、Origin/动作头验证及 8 KiB 请求限制。
- 账户与租户来自服务端 registry；浏览器不能提交账户作用域或审计 actor。
- LIVE 只读；资金/组合风控未预配置的账户不可发布。
- 专用 DB 角色新增 SELECT 和受限函数 EXECUTE，无通用业务状态或订单写权限。
- 这仍是单 owner 控制台，不是完整 SaaS 登录/RLS 隔离改造；DB 角色本身可读取多租户业务表，
  应用层负责账户授权，不能把此权限模型描述成数据库级强租户隔离。
- 不读取/展示账户 API 密钥；没有新增本地业务状态文件。

发布顺序：并发创建查询索引 → 原子新增审计表/函数及授权 → 使用实际 Web 角色执行 preflight
→ 发布独立 account-admin Web 版本 → 设置 `V2_ENABLE_STRATEGY_CONSOLE=1` → 仅重启 account-admin。
缺索引、函数或 SELECT/EXECUTE 权限时拒绝启动，不能带故障开放控制台。

迁移：`db/migrations/20260928_strategy_console.sql`。
授权和索引：`deploy/v2-testnet/strategy-console-{grants,indexes}.sql`。
并发索引必须在事务外执行；中断后检查 `indisvalid/indisready`，不能仅依赖 IF NOT EXISTS。

回退仅退回 account-admin 发布目录并移除本次功能开关；不删除审计表/历史、不自动回退账户参数。
查询索引可保留。若用户已发布配置，应单独审查并通过版本化恢复操作处理，不能直接覆盖数据库。
独立 Web 发布不部署新的交易执行/行情策略代码，所以旧运行版本暂不产生新增定仓解释和浮盈浮亏采样。

## 2026-09-30：只读风险收益复盘增量

根据风险/仓位公式审查，增加 `services/v2_review_risk.py`，由既有按需复盘调用。
本次不改变定仓、杠杆、保护、入场或退出条件；不启用量化候选。

- USDT 线性合约的 1R：实际开仓名义金额与实际数量乘冻结决策止损价之差，按多空方向取正。
  这是相对原始决策止损的毛风险，不是账户收益率，也不证明交易所接受的保护价格。
- 实现净 R = 已完整结算净收益 / 上述风险。费用、资金费已在净收益中，不重复扣除。
- 原计划风险按实际成交数量缩放，再比较入场风险偏差；部分成交不使用整单计划风险作分母。
- 输出样本平均净收益、平均净盈利/亏损、实际盈亏比、净 R 均值及有效/缺失样本数。
  仅为描述性统计，不提供预测胜率、未来期望、盈利认证或破产概率。
- 按来源、入场模式、方向、策略版本和参数摘要分组；总账户均值仍是混合历史样本。
- 缺失、非有限数、原计划金额矛盾、止损落在实际成交盈利侧时保持未知；不使用最终平仓价推造止损。
  未可靠记录的目标价不推造计划盈亏比；未结算、未来平仓与维护交易不纳入净 R 均值。
- 净亏损超过初始毛风险只标记复查，费用和资金费也可能导致超过，不直接归类执行故障。
- 前端：策略工作台 → 交易明细 → 生成只读复盘。新增风险摘要、版本化分组和逐笔风险列；
  账户/时间窗切换清除旧结果，兼容未带新字段的报告，沿用限时查询与 60 秒缓存。
