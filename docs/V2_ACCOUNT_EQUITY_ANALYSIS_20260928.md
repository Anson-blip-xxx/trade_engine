# 账户净值与资金质量：只读分析交付

日期：2026-09-28。入口沿用 `/accounts/strategy`，展示时区 UTC+8。
本轮在已上线的策略分析中心补充账户净值观测，不改变交易参数或执行逻辑。

## 已实现与口径

- 读取 PostgreSQL `capital-snapshot-v1` 的不可变版本历史，不查询交易所、不写业务状态。
- 展示交易所账户报告的净值、钱包余额、浮动损益、已用/可用保证金。
  单独展示现有风险预算基数，避免把 1000U 演练本金当成交易所账户余额。
- 浮动损益按快照中 `totalMarginBalance - totalWalletBalance` 计算，不能与整笔交易净收益相加。
- 原始净值变化为末次减首次观测值；原始采样峰值降幅为正历史峰值下的最大相对下降。
  允许负净值及超过 100% 的原始下降，不通过截断为零隐藏赤字。
- **原始变化/降幅不是策略收益率或策略最大回撤**：充值、提现、划转、手工交易、其他系统活动均可能影响账户。
  `strategy_return_pct` 与 `strategy_drawdown_pct` 保持 null，不计算未经证明的资金流调整收益。
- 现金事件按完整账户作用域读取，展示类型、币种、金额、数量。原始收入事实不与 episode 结算再次累加。
  快照期间的钱包变化减已记录 USDT 现金流显示为“对账残差”，不是利润。
  期间定义为 `(首次快照采集开始时间, 末次快照采集开始时间]`。
- 未估值的其他币种或现金读取截断时不计算残差；无转账记录不代表无转账，残差为零也不证明采集完整。
  快照时间不是交易所精确结算切点，边界现金事件需核对原始证据。

## 数据质量与隔离

1. 按确定性 state ID 和版本倒序，最多先读取 5001 条，处理最新 5000 条；不扫描全站 JSON 历史。
   Python 依据观测时间筛选请求窗口，读取截断、有效样本数、首尾时间、最大间隔均显式返回。
2. 逐条检查账户作用域、核实快照来源标签、观测/到期时间、金额类型和所需字段。
   未来观测、损坏字段、删除记录、错误账户数据不会参与曲线。
3. 相同时间/相同数值归并；同一时间出现冲突金额时整组排除，不能任选一条冒充准确。
   版本时间倒退会标记，按观测时间排序展示。最新记录无效时，不把旧记录标成当前有效。
4. 图表最多 240 点，分桶保留首尾与净值极值；统计用压缩前全部有效样本。
   只画观测点，不用连线/插值补齐没有采集的区间。
5. 仍是采样数据，不保证覆盖所选窗口起点或交易所每个价格变化。
   过期样本仅用于历史观察，不作为实时账户情况或开仓许可。
6. 净值报告位于只读事务内的 savepoint。冷查询超时回退为 `QUERY_TIMEOUT`，
   不使外层事务失败，也不隐藏原有已结算交易报告；其他未知错误不被伪装成空数据。
7. 账户选择、授权和迟到响应防护沿用既有控制台。切换账户、空数据或请求失败时清空旧面板。
