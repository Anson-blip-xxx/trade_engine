# 方向策略最终账户结算

`services/v2_directional_settlement.py` 实现正式 S6/S8 Testnet episode 的最终结算阶段，
将开仓前账户基线、平仓成交、交易所收入、平仓后账户状态和 PostgreSQL 账本绑定。
它没有交易所写入接口，仅使用 GET 查询并写入 v2 PostgreSQL 权威账本。

## 结算证据链

1. 调用方向策略现金核验，重新读取整个成交时间窗的手续费、realized PnL 和资金费。
2. 从该 episode 唯一 OPEN 订单对应的 `opening-readiness-v1` 获取发送开仓前的
   完整账户库存和钱包余额。要求当时门禁为 READY、无阻断、无读取失败。
3. 持有账户级 session lock，读取本地账本前快照，取得交易所全账户最终库存，
   再读取本地账本后快照。最终库存持久化到 `account-inventory-v1`。
4. 核对交易所无持仓、无普通挂单、无条件单，本地开平量归零、订单终态且唯一归属；
   基线必须早于第一笔成交，最终账户快照必须晚于最后一笔成交和现金核验。
5. 钱包变化必须精确等于现金核验的 provisional_net_pnl。金额不一致时不自动补差。
6. SERIALIZABLE 事务内重新核对基线版本/内容、最终库存、现金观察和本地事实；
   按发生时间归属资金费，逐笔增加 accounting_revision，重新计算账本净盈亏。
7. 仅当重算净盈亏仍等于钱包变化，原子写入资金费调整、收入归属、settlement、
   episode SETTLED、风险释放和领域事件。任一步失败，整笔事务回滚。

统一 daemon 配置的 SANDBOX 外部持仓排除会原样传入最终 coverage，与开仓 readiness、
symbol settings 和保护阶段保持一致。它只排除明确标的的持仓数量；任何普通/条件挂单、
采集期间仓位变化或 V2 本地认领仍阻断结算，最终 inventory 保留排除列表和原始持仓证据。

最终 proof 保存账户范围、基线/最终库存 ID 与摘要、现金摘要、资金费 income ID、
钱包变化、净盈亏以及四项完整性布尔值。摘要用于绑定证据内容，原始事实仍分别保留。
重复运行已 SETTLED episode 不会再次分配资金费或重复结算。

## 统一循环行为

`DirectionalSettlementStage.run_once()` 可直接替换 `TradingPipeline` 的 settlement port。
有未结算 episode 且任何证据缺失时返回 BLOCKED，循环不产生新策略订单。
成功结算旧 episode 后，本轮返回 CLEAR，才继续行情、S6/S8 准入。
阶段级锁阻止副本并行扫描；账户级锁覆盖最终库存到事务提交的窗口，协调现有执行、
保护、撤单和结算写入者。交易所 REST 观察本身不具备原子性，因此仍依赖专用账户、
单写者协议和前后本地事实一致性检查。

## 严格失败策略

以下情况保持未结算：缺失/被阻断的开仓基线、多个 OPEN 订单、时间顺序倒置、
现金证据被替换、账户锁忙、交易所仍有仓位或挂单、账户读取失败、钱包差额、
收入不完整、外币费用、重叠 episode、本地事实变化、账本重算不符。
最终账户快照即使失败也保留，作为可追查诊断，不构成结算许可。
