# V2 生产批次与行情上下文

第 1 项内部检查点：新增 S0/S3 输出适配器、事务批次登记和真实 Redis 上下文读源。
旧常驻循环尚未切换，S3 生命周期/冷却仍需迁移到 PG；不是生产上线验收。

## 责任边界

- `services/v2_market_publishers.py`：接收已计算的 S0 状态/S3 特征和已管理事件，
  不重新计算指标，不导入旧运行模块。有限浮点观测转为十进制字符串，拒绝 NaN/Inf；
  这不是把浮点财务运算变为精确计算，交易金额仍走独立 Decimal 账本。
- `v2_core.producer.ProducerPublisher`：规范化并冻结批次，PG 同事务登记全部
  信号及 `v2_producer_batches` 回执。PG 只保留批次内容摘要和信号 ID，不存全量行情历史。
- `RedisMarketContext`：行情当前快照，键为 `v2:market:<environment>:<source>:<symbol>`，
  S0 使用 `*` 全局范围；S2/S3 必须指定合约。不是交易授权或去重权威。
- `ContextProvider`：读 Redis 封装并校验身份、环境、时间和信号要求；被策略使用的
  实际快照进入 PG 不可变决策证据。全量历史分析仍属 ClickHouse，历史发布接线未完成。

## 批次与重试

`publish(frame_id, observed_at, contexts, events)` 的 frame_id、原始观察时间和
event_id 均由生产者显式提供。禁止重试时改为当前时间/新 UUID，禁止按数组位置
临时创造事件身份。事件 ID 标识一次发布（ACTIVE/UPDATE/END 的每次修订），不是
可重复覆盖的 symbol+type 或整个事件生命周期 ID。

按 source/environment/frame_id 唯一，摘要覆盖完整规范输入，事件顺序也属于内容。
同批同内容重放返回原 signal_ids；同批不同内容或旧 event_id 内容变更明确冲突。
同一生产者范围使用 PG 事务 advisory lock 序列化，避免不同批次以相反顺序争抢事件唯一键。
任意一个事件失败整批回滚，不留下前半批。回执不可修改/删除。

S0 仅登记空信号批次并投影全局状态，不产生开仓命令。S3 END 规范为 EVENT_END，
原事件类型和状态仍在特征中，不能把结束事件直接当新的 TREND_UP 等开仓信号。
真实消费规则仍须明确处理 EVENT_END，本适配器没有新增自动平仓行为。

PG commit 或提交回执失败直接抛错，在这条调用中不写 Redis；确认失败后用原批重试。
确认 PG 成功后才逐条投影 Redis。缓存故障不撤销已提交信号，而返回
`status=RECORDED, market_status=UNAVAILABLE` 和不含连接信息的异常类别。
调用方不能只看 RECORDED 就认定行情就绪，必须监控/重试同批修复投影。
原始批内容由调用方/上游重放源提供；若旧行情无法重放，可发布新的真实观测批次，
不能从本地业务文件恢复，也不能伪造旧时间。常驻重试接线仍未部署。

## 乱序、丢缓存与来源约束

Redis 使用原始观察毫秒数 + 1 作版本，Lua 原子比较整数串：旧帧不能覆盖新帧，
同时间不同内容返回冲突。读源校验完整封装与摘要，不把畸形/丢失视作有效行情。
这是假设受控 Redis 访问权限下的完整性校验，不是替代认证的数字签名。

可执行生产信号携带 publisher 生成的 `producer_context`，调用方不能覆盖此保留字段。
无行情的生命周期 EVENT_END 可以不含该引用；它只能记录终态，不能进入策略开仓评估。
决策读源必须包含对应来源，且观测时间不早于信号引用；相同时间必须摘要相同。
更新的真实快照可以参与新决策，但仍须满足上下文新鲜度和原信号截止时间，并被
完整记录。此前已冻结决策的恢复不换快照、不延长有效期。

因此，信号已入 PG 但新缓存写失败时，旧缓存即使尚未超过一般 TTL，也不能满足
新信号的快照要求。任务等待或到期，不会悄悄使用较旧场景执行。
