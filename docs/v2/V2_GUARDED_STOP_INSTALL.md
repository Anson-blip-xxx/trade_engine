# 已成交仓位的受控止损创建入口

2026-09-21：新增 `v2_core.protection_install.GuardedStopInstaller`。
这是 PM 接线所需的受控创建组件，不是完整 PM，也没有在运行服务中开启创建权限。

## 创建前置条件

默认 `allow_create=False`，没有已有登记时不访问交易所、不写保护登记。
只有显式开启、Binance Testnet、STOP_MARKET 类型才进入创建检查：

1. 持有与协议维护/恢复巡检相同的账户 session advisory lock。
2. 读取 PG 事实、交易所全账户清点，再读取 PG 事实；发生变化立即拒绝。
3. 账户覆盖核验仅允许“缺少确认止损”，其他阻断项一律拒绝，包括未知仓位、
   未确认订单、普通挂单、保护条款不匹配及同品种多个 owner。
4. 指定 episode 必须在该账户有正的已确认净成交，symbol 和保护方向相反且匹配。
5. 注入的标记价格/最小价格步长必须绑定 symbol、SANDBOX、有效毫秒时间。
   价格证据不超过 10 秒；止损为精确 tick 整数倍，且在相应触发方向的价格一侧。
6. 在 PG 事务中锁住 episode 意图，再次核对全账户事实，原子写入 SENDING 和
   创建依据；事务提交后才允许 POST，POST 前还检查一次期限。

完整依据含账户、spec、原始 inventory、事实摘要、价格参考和到期时间，保存在
既有保护登记 `creation_proof` 中；没有新增 schema 或本地业务文件。
价格回调必须由可信、只读的行情/规则适配器提供；本轮仅测试注入契约，
并未把任意调用者参数等同于可信的生产行情，也未新建真实行情适配器。

## 恢复与权限边界

已有登记始终调用原身份查询恢复；不依赖新行情、不要求再次开启创建开关。
价格发生改变会触发已有身份冲突，不生成“新身份新止损”。
网络发送限定 `/fapi/v1/algoOrder` 的精确 STOP close-all 参数；不支持普通开仓或 DELETE。
提交丢响应、写回失败或登记后证据过期时，原 SENDING/UNKNOWN 仍保持只查询恢复，
不会因查不到单而再次 POST。可能出现“登记已写但实际未发送”的待处理状态，
这是保守失败，不会谎报保护已存在。

`AccountCoverageAudit.facts(connection=...)` 可加入调用者已有事务；默认独立调用仍
使用 REPEATABLE READ。受控创建将事实校验和登记放在同一事务，网络不在事务内。

## 尚未完成，不能放宽的门禁

- 部分成交开仓/未终态订单目前明确拒绝；“部分成交即受保护”仍未实现。
- 只支持创建 STOP；撤换、追踪止损、止盈管理、所有关闭竞争未接通。
- account lock 只能约束遵循约定的 V2 写入者。外部手工交易和不遵循锁的程序
  不受该锁约束；REST 也不是原子快照，不能宣称消除了所有交易所竞态。
- 尚未与真实策略/常驻 PM 调度连接，没有在 Testnet 真实持仓上验收本新入口。
- 开新仓前必须确保该品种前一 episode 的保护完成清理；本组件不负责这一发布门禁。
- 当前 ZORA 账外仓仍遭交易所 -2022 拒绝，只读账户诊断保持 BLOCKED。
  本轮没有新增仓位、替该仓创建保护、重发平仓或绕过 reduceOnly。

因此本次只完成“已确认、独占、全成交仓位的受控创建基础组件”，
不能关闭完整 PM、真实策略自动闭环或最终上线验收任务。
