# V2 策略决策入口契约

本轮交付的是新运行时的持久化决策入口，不表示旧 S6/S8/S7/PM 已切换。
没有启动生产进程、执行交易或改写运行服务配置。

## 固定一次决策

`StrategyWorker` 接受明确的账户/环境/产品/策略范围、信号来源、配置版本、
配置快照、纯决策函数和最大有效期。`consume(signal_id, context=...)` 从 PG
读取原信号，保存规则判断与证据，然后调用 V2 意图入口，最多准备一个市价单。
不构造交易所连接，不提交订单，不把 PREPARED 解释为成交。

- 账户范围与策略构成 consumer；同 consumer/signal 只允许一个持久决策。
- 决策函数接收信号、上下文、配置的副本，只能返回 `StrategyDecision`。
  金额使用十进制字符串；配置与证据拒绝凭据字段和浮点 JSON。
- 并发时函数可能运行多次，必须无副作用。首个提交的决策生效，其余工作者复用；
  不能在函数内下单、发消息、写业务状态或修改共享配置。
- `v2_strategy_decisions` 与配置/判断证据同事务，信号复合外键防止错挂。
  首次持久决策之后，即使进程重启、部署配置变化，也不重新解释原信号。
  配置更新应创建新 worker，禁止并发修改同一 worker 的部署参数。
- 有效期取原信号期限与本次最大有效期中较早者。入场等待容量不延长期限；
  决策落库但意图未登记就中断，也必须按原期限恢复。

## 返回状态不等于交易结果

| 状态 | 含义与调用方处理 |
| --- | --- |
| DEFERRED | 信号观测时间还在未来；未计算、未消费，等待时间有效后再处理 |
| IGNORED | 规则拒绝，保留配置、上下文和理由；不可换配置复活 |
| EXPIRED | 信号或已保存决策过期；不补单 |
| PREPARED | 意图和订单身份已持久化；未提交交易所，更不代表持仓 |
| WAITING_CAPACITY | 同合约已有活动 episode；当前意图未创建订单，按原期限重试 |
| INTENT | 同一 consumer 已有其他入口登记的消费回执；读取原 intent，不重开 |
| CONFLICT/UNKNOWN | 沿用意图入口含义；不得换 request_key 绕过去重 |

数据库失败、决策函数异常、参数错误不伪装成容量等待。只有 PG 的明确活动
episode 唯一约束冲突会返回 WAITING_CAPACITY；其他异常保留给可观察的重试流程。

## 只读追溯

开仓意图继续使用 `TradingData.trace(intent_id)`；无订单的拒绝/过期判断使用
`TradingData.decision_trace(decision_id)`，包含原信号、配置、上下文、规则理由和回执。

使用已有只读连接配置运行 `python3 -m v2_core <decision_uuid> --decision`。
该选项不能与 `--pnl-currency` 混用；CLI 不初始化 schema，也不提交交易。

## 旧入口迁移边界

检查确认 `strategies/S6.py` 和 `strategies/S8.py` 仍调用 shared_executor 的旧开仓
函数；`shared/s6_auto_trader.py` 还有独立开仓入口；PM 仍有自有开平仓和条件单路径。
这些路径未在本轮偷偷重定向，也不能加载旧模块作为“纯决策函数”。

下一步接线须将指标/规则计算与读写、持仓维护、发送通知分离，保持策略规则 QA。
S7 网格必须使用多订单计划，不能把此单单入口当网格实现；PM 平仓仍须走持久
平仓预留与 reduce-only，保护单生命周期仍为上线必需项。
批量消费已有下述持久调度接口；尚未安装常驻轮询服务，也不在重启时补发交易请求。

本轮 QA 覆盖并发首个决策生效、配置/上下文防污染、期限保留、提交回执丢失、
事务回滚、拒绝/过期可追溯、已消费信号不可复活、策略隔离以及容量等待自动过期。

## 持久批量调度

`StrategyScheduler(worker, context_provider=...).run_once(limit=100)` 仅评估/恢复
决策及准备订单，从不调用 dispatch。上下文提供者必须只读、无业务副作用，所有
外部查询必须设置有限超时；租约不是对阻塞函数的抢占式终止机制。

- `v2_strategy_tasks` 按 consumer/signal 唯一。每轮发现尚未入队的信号，不用
  时间/UUID 高水位，因此早期提交延迟和坏信号不会永久遮住后来的信号。
- 用 PG 时间排期和租约，逐条 `SKIP LOCKED` 领取，故障隔离并退避；保存异常类名，
  不保存可能含凭据的异常文本。数据库整体不可用时本轮失败，不转向本地文件。
- `INTENT` 回执不是调度完成：同合约占用时继续保留任务，槽位释放后复用原决策，
  或按原期限过期；已完成订单准备的任务不会再被调度器自动提交。
- 完成条件读取已提交的回执、意图状态和订单事实，不依赖回调返回值。
  回执确认失败由租约到期恢复；旧令牌不能更新新领取者的排期。
- 已存决策、已消费、未来信号及已过期信号不调用上下文提供者；行情源故障
  不阻止已到期信号终结，也不允许用新上下文重写已固定的决策。
- 租约到期时可能发生重复纯计算，真正的幂等边界仍是持久决策和意图唯一性，
  不承诺回调 exactly-once。失败不会自动丢弃任务，需要运行层监控积压和错误。

调度完成只表示信号已获得明确处置或订单已准备，不表示交易成交、盈亏已确定
或保护已生效。未完成的运行接线统一见 [剩余工作](V2_REMAINING_WORK.md)。
