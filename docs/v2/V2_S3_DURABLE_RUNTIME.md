# S3 持久生命周期与检测接线

## 已实现的独立 V2 功能

`services/v2_s3_runtime.py` 接收显式观测帧，调用现有纯 `s3.detector`，
以纯函数实现 FAILED_BREAKOUT，再由 `S3FrameProcessor` 处理生命周期。
不导入旧 `strategies/s3_orderflow.py`，没有网络、常驻线程或交易调用。

一个 PG 事务包含：生产者范围锁、生命周期和突破状态 CAS、不可变状态历史、
帧回执、稳定身份信号、生产批次回执。任何一步失败全部回滚；PG 提交确认后
才更新 Redis。业务状态不落本地文件，不以 Redis 或进程内字典为权威。

同环境、同 frame_id 的输入必须完全一致；重试复用原事件、配置、有效期，
即使重启、升级配置或原信号已过期也不重新检测。提交成功但响应丢失后同样如此。
Redis 故障可以用原帧重试修复，不新增状态修订或信号。

新帧必须使用来源观测时间，且严格晚于已提交帧。该接口面向一个有序批次流，
不是多个独立 symbol 的同时间写入接口；上游必须先组批。不得给旧输入刷新时间。

## 生命周期语义

- 身份按 symbol/type/direction 分开；episode_id 由首次帧确定，每次输出有独立修订 ID。
- 首次 ACTIVE；30 秒冷却达到，或强度变化达到 20，输出 UPDATE。
- 每次候选仍存在都更新 last_seen，冷却抑制不会伪造消失；since_ms 保留首次出现时间。
- 同 symbol 有有效覆盖但候选超过 300 秒未出现，输出 END；恰好 300 秒不结束。
- symbol 未覆盖表示未知，不自动 END；显式 removed_symbols 才能在无行情时结束并清理突破状态。
- END 映射为 EVENT_END；策略与调度器无需行情或策略回调即可记录 IGNORED。
  END 不开仓，也不意味着自动平仓。真实平仓须走后续 PM/风险策略。

失败突破保留 0.8% 突破、0.2% 回撤/延续门槛，采用 Decimal 价格；超过 7.5 小时
先过期，不补发旧失败信号。这与旧函数“先发事件后超时”的顺序有意不同。
旧浮点边界改为精确十进制边界，强度限制 0–99。普通指标检测仍沿用既有纯规则。

## 输入与恢复边界

实际适配器要求完整 15m/1h/4h/24h change 窗口、15m 非负有限量比、至少 2 根 4h
和 3 根 15m 原始 K 线，最新在前；验证正价格/OHLC 范围及已提供时间不能来自未来。
不完整帧拒绝并回滚，不用默认零当成行情。来源级新鲜度、窗口计算和时间真实性
仍须在后续行情采集器接线中验证；本模块不能证明调用者没有伪造 observed_at。

帧输入摘要与输出、配置保存在 PG，完整行情历史不保存在本表。原帧重放需要上游
提供相同输入；历史行情归档/重建仍待接线。Redis 丢失时不能从本地文件恢复业务状态。
受影响信号等待新鲜上下文或到期，不降级开仓。

状态是有界的整帧快照：最多 1000 个覆盖 symbol、1000 个候选、10000 个活动事件，
输入和状态各最多 8 MB。生产者范围锁串行化计算保证一致性，但存在全量历史写放大；
上线前必须测实际频率/规模、PG 超时及锁等待，并评估分片与历史保留策略。

SQL 是独立新库初始化契约，不是已运行数据库的在线升级脚本。
本阶段没有部署新服务、替换旧扫描循环、修改运行库、访问交易账户或执行交易。

## QA 范围

真实隔离 PG 验证并发重放、重启冷却、配置变更重放、状态/信号/批次共同回滚、
提交回执丢失、缓存修复、乱序/冲突拒绝、真实检测器和突破状态重启接线，以及
无行情 END 的调度终态。纯测试覆盖边界强度、时间、断流、移除、再次激活及坏行情。
这些不是全生产策略或交易所的完整上线验收。
