# TradingView V2 Integration

TradingView is an optional candidate-signal producer. It never owns positions,
submits orders, bypasses V2 risk, or decides exits.

## Coverage limitation

Pine cannot enumerate every TradingView/Binance symbol. TradingView documents
that custom-script alerts must be created per symbol, or a script must explicitly
request other symbols; a script is limited to 40 unique request contexts (64 on
Ultimate). Therefore “all currencies from one Pine alert” is not a supported
design.

The production design is:

1. Binance USD-M `exchangeInfo` is the authority for the eligible universe.
2. TradingView uses `BINANCE:<symbol>.P` charts only.
3. The same `tradingview_v2_universal.pine` source is reused for each configured
   chart/alert (or supported watchlist alert, if the account UI permits that
   custom condition).
4. V2 normalizes the TradingView ticker and rejects foreign exchange prefixes.
5. Before any order, the fresh Binance account-context collector requires one
   exact symbol with status `TRADING`, contract type `PERPETUAL`, matching quote
   asset, complete order filters and account symbol configuration. Failure is
   `SYMBOL_NOT_TRADING` / `ACCOUNT_SYMBOL_CONFIG_MISSING`; no order is created.

This final Binance gate is mandatory even if a TradingView watchlist was built
from Binance symbols, because listings and trading status can change after alert
creation.

## Alert setup

- Chart: a standard 15-minute `BINANCE:*USDT.P` perpetual chart.
- Script: `docs/tradingview_v2_universal.pine`.
- Condition: `Any alert() function call`.
- Webhook URL: the deployed HTTPS `/v2/webhooks/tradingview` endpoint.
- Message: generated by `alert()`; do not replace it in the dialog.
- Secret: a random, ingress-only secret. Never use a Binance credential.

The server endpoint accepts only ports 80/443 and must acknowledge inside three
seconds. The ingress persists first and returns; exchange reads and trading are
asynchronous.

## No-domain test phase

Do not expose the internal WSGI listener or use plain HTTP with a secret. A
temporary HTTPS tunnel may be used for Testnet acceptance, but its generated URL
is not a production dependency and every URL change requires recreating the
TradingView alert. Production requires a stable HTTPS hostname (owned domain or
an explicitly approved stable tunnel hostname), TLS termination, source
allowlisting/rate limits and request-body logging disabled.

## Event identity and time

The producer identity is deterministic:

`tv:<standard ticker>:15:<bar close Unix ms>:<signal>`

Retries preserve the same identity. `observed_at` is the confirmed 15-minute bar
close, `expires_at_ms` is derived from that original time, and all timestamps are
absolute Unix milliseconds. UTC+8 conversion is display-only.
