# V2 策略层重设计与验收计划

日期：2026-11-25，更新于 2026-11-26 UTC+8。状态：P1 已推进到 PG 部署版本、机会准入、OPEN 授权、新旧计划资本适配、新计划保护/退出/现金结算、显式仅管理进程、typed 交易所开仓闸门和准备恢复、有审计的重复信号终态，以及限时任务监督基础设施与结算轮转修复；并发入场/结算进程与新入场 worker 接线仍未完成。未启用新策略，交易保持用户要求的暂停状态。

目标是找到扣除成本后仍有价值的入场与持仓方法，并让有效策略能够替换无效策略。保留 V2 的账户隔离、交易所连接、资金预留、订单恢复、原生保护和账本；重设计机会发现、策略决策、策略版本绑定和对照评价。本计划不授权实盘，不调整当前账户参数，不重启服务。

## 当前实现范围

第一轮基础合同以仓库提交 `b93d7411c749aaf76337a8dfa41c440a46805638` 为代码比较基线，不把该提交自动认定为所有运行进程的版本。该轮新增 `v2_core/strategy_registry.py` 和 `v2_core/strategy_plan.py`，没有变更运行配置、数据库结构和服务部署。

- 注册表只接收显式列出的策略版本、计划类型及处理器名称，不动态导入或执行插件。部署快照区分 SHADOW、ACTIVE、DRAINING、OFF；ACTIVE 也不授予下单权限。
- 统一计划保存账户、机会、数量、杠杆、初始止损、风险预算、部署代数及退出版本。数值校验沿用精确金额规则；账户及配置由对象独立复制，重复 JSON 字段和超限配置不能恢复。
- 现有 `DirectionalStopRecovery.plan()` 改为通过 `LegacyDirectionalPlan` 读取原 PG 准入证据，保留原版本、账户、producer、方向和数量检查。保护读取不新增信号有效期、模型结果或研究字段要求，不改写历史证据。
- 旧版原生初始止损仍来自原计划；旧版软件退出仍读取当前账户策略。这是已有行为，不声称旧仓已具备开仓时冻结的完整退出版本。部分成交和平仓的实际剩余数量继续由账本负责。
- 新绑定的 consumer 与现有账户加 producer 身份兼容，代码版本和部署代数不进入 consumer。第一轮只验证身份契约；后续部署与机会准入实现见下节。

P1 的资金预算适配进展见第三轮，新计划保护/退出及结算进展见第四轮，仅管理进程见第五轮，交易所闸门及准备恢复见第六轮，重复信号终态与调度 ACK 见第七轮，限时任务基础设施与结算公平性见第八轮；仍须完成并发调度及新入场 worker 接线。随后才开展 P2 两个确定性策略族的共同机会对照。隔离合同通过不代表新策略已经在运行交易，也不代表盈利改进；运行验收和研究窗口尚未开始。

隔离 QA 的 22 个相关测试文件共 608 项通过，其中包含 181 项纯合同测试及 10 项真实 PG 准入证据兼容用例。交易所使用模拟响应，外部 TCP 被测试边界禁止；未调用真实交易接口。首次回归发现两条测试夹具缺少撤单前的完整成交核验证据，补齐夹具后整组重跑通过，未放宽订单安全约束。详见 [基础合同验收记录](../qa/20261125_strategy_layer_foundation.json)。

### P1 第二轮：版本切换与永久机会准入

以停止并完成沙盒平仓后的源码提交 `3b9f25e` 为增量基线。本轮仅修改开发工作区，不复制到 `/opt` 的运行目录，不恢复执行路由、不重启交易服务、不操作交易数据库或交易所。PG 和 Redis 测试均使用独立临时实例，外部 TCP 在测试边界禁止。

- `strategy_deployment.py` 复用 PG BusinessState 和不可变历史存储部署绑定；账户、实例、代码、配置和 generation 一起校验。发布使用 CAS，旧请求重试不会覆盖较新版本；墓碑、历史残留或损坏数据拒绝入场，不回退成“从未管理的旧策略”。
- `strategy_plan_admission.py` 将完整计划、配置、决策证据、开仓意图、可选信号消费回执和永久机会回执放入同一事务。机会 ID 在同账户内跨策略实例、版本和来源唯一；再次收到同机会不再开第二单，精确重放只读返回原意图。上游仍必须给同一真实机会生成一致 ID，此处不声称已经实现 TV/S3 的机会识别。
- 有信号时使用既有 `signal → intent → account` 锁序，无信号为 `intent → account`；部署发布只取账户锁，不在持锁期间扫描或锁定意图。输入尺寸与准入数据库等待有上限，事务里不调用模型或交易所。
- `Orders.prepare` 和 `OPEN → SUBMITTING` 共用最终校验：当前部署允许入场、版本完全匹配、数据库时间未过期、计划与意图绑定、永久机会回执及历史一致。直接调用通用 IntentStore 也不能绕开机会回执。提交许可的订单事件同时记录部署证明和已有风险预算证明。
- 切换时已经提交许可的 `SUBMITTING/UNKNOWN` 保留原身份继续查询，不重发订单，不声称可以撤回已发请求。`CLOSE`、保护及核对不增加 entry generation 检查；额外 OPEN 数量仍要通过新入场闸门。`DataRuntime.accept_open` 准备阶段的确定性拒绝终结未执行意图，Runner 派发拒绝终结 PREPARED 订单；新准入 adapter 的失败会整笔回滚，不声称已为上游每个重复信号记录消费终态。
- `strategy_plan_store.py` 只从原意图及原证据读取冻结计划；到期或停用不妨碍历史读取，有新计划标记但内容不合法时不能改用旧字段。旧 schema 夹带新计划也拒绝，避免绕过校验。
- 第二轮交付时，新计划不能进入旧的动态资金模型，明确返回 `STRATEGY_CAPITAL_ADAPTER_REQUIRED`。下节第三轮已用完整的新旧资本适配取代这一占位拒绝；缺少显式资本合约仍拒绝，固定旧名义上限不再能绕过新计划的资本及组合风险要求。第二轮固定名义预算测试是当时的协议验证，不是新策略全流程完成证据。
- 两类新 namespace 不在诊断清理 allowlist 内，部署历史和永久机会回执不能按诊断数据过期清掉。现有 sandbox rebuild 对未知 namespace 明确拒绝；在添加完整安全迁移前不能把它们加入可丢弃运行状态名单。

本轮最终隔离回归覆盖 30 个相关测试文件，1,121 项全部通过（含 144 项新增部署、准入与派发测试）。这不是全仓库、真实交易所或新策略盈利验收；故障回归中修正了测试夹具的 API 参数、模拟成交证据、资金池配置及部分成交平仓数量，没有放宽业务安全检查。详见 [部署与准入验收记录](../qa/20261125_strategy_deployment_admission.json)。

后续按以下顺序继续，不跳过阶段验收：

1. 新旧计划共用资金读接口：本轮实现范围和限制见下节，完整执行链仍须后续验收。
2. 原生保护、软件退出、现金核验、结算、分析完整读取新计划及冻结退出版本；不能只改 producer 过滤或给新策略填旧分数。
3. 独立管理调度和 worker 接线；同机会重复、计划过期等预期拒绝要形成有审计的消费终态，不把第二个 TV/S3 事件留在无限重试中。策略或模型卡住不能阻塞保护退出。
4. 新计划完整模拟生命周期、恢复故障、资源压力验收；随后才进入新策略样本对照和用户授权的测试环境运行。

### P1 第三轮：共享资本预算与不可变预留

以 `6c6ed7a` 为增量基线，只修改 V2 开发工作区。没有恢复交易、复制运行文件、重启服务、调用交易所、变更运行数据库或配置。统一 QA 仍使用临时 PostgreSQL/Redis 和模拟交易端口。

- `strategy_capital.py` 从原意图和不可变证据解析新计划，批量持仓读取复用同一身份校验；不为新策略伪造 S6/S8 的分数、方向计划或 sizing。候选及待用保证金在现有账户锁和事务内复核，未知证据不当作零。
- 新绑定必须显式冻结 `config.capital`：`schema=strategy-capital-v1`、`roundtrip_cost_fraction`、`price_drift_fraction`。缺少合约时拒绝，不从旧字段猜测成本。`planned_loss` 是声明的风险下限，不自动解释为已包含或未包含成本，实际预算取声明值、原始不利价格区间风险、当前固定止损风险和原预留风险的最大值。
- 新计划必须启用资本和组合止损风险预算，不能借有限旧名义上限绕过；动态资本池最多使用基数的 70%，保留至少 30%。当前风险、保证金和杠杆限制仍叠加生效，不把 70% 当成必须用满的目标。
- 新旧 HELD 共同占用组合风险。新 HELD 必须具有匹配计划摘要、原止损预算和原保证金；参数下调不释放原预留。部分平仓和 UNKNOWN 不释放完整风险，最终结算/终止仍由既有账本规则决定。
- 保证金与止损风险分开：完整成交、已在快照前核验的开仓由交易所账户保证金覆盖；未成交、部分成交和快照时间重叠保守保留完整待用保证金。后者可能重复计入部分交易所占用，证明中显示 partial/overlap/incomplete 计数；不声称精确支持未提交子单余量，也不因一次普通部分成交就抛永久全账户异常。
- 首版新计划只允许一次全量 OPEN 请求；订单自然部分成交可以继续核对和退出，但不能自动补开余量。提交前若资金/成本变化要求超过原预留，明确拒绝扩额，不以“当次检查通过”代替未写入的资金增补。精确子单分配及原子风险增补未实现，不隐式启用。
- 杠杆依据冻结新计划及可选资本证据；存在但损坏的证据即使低杠杆也拒绝。维护保证金阶梯、深度、价差、标的和冻结观察时间需有效；高杠杆仍需原有安全与流动性检查，并考虑当前入场到固定止损的风险，不仅比较初始止损比例。
- 数量、价格等持久化事实不修改；合法乘积可以超过 18 位小数，派生值精确计算，最终保证金/风险上取 18 位，避免再次因中间值精度误拒绝。

第三轮交付时没有开放新的运行入口，保护/退出、现金核验及收益归属当时仍未适配；第四轮接续以下工作。worker 与独立管理调度仍未完成，P1 尚未整体完成，不恢复旧策略试单。

第三轮最终隔离回归覆盖 43 个相关测试文件，1,399 项全部通过，其中新增资本适配用例 294 项。源码摘要在测试前后核对一致，Ruff 和 diff 检查通过。验收结果与中间失败记录见 [资本适配 QA](../qa/20261125_strategy_capital_adapter.json)。这些用例验证工程资金约束，不是全仓库测试，不证明策略盈利或实盘成交。

### P1 第四轮：历史计划保护、冻结退出与核验结算

- 保护、软件退出、现金核验及结算扫描通过共同生命周期条件选择旧 S6/S8 与新 `strategy_plan`；畸形新标记也会被选中并诊断，不能回退旧字段或悄悄消失。OPEN 自动派发仍维持旧范围，没有由扩大持仓扫描暗中启用新策略。
- 新原生保护从已绑定 intent/evidence 读取原始止损，复核账户、合约、方向及完整 OPEN 数量。部署 OFF/DRAINING、入场过期或当前配置变化不撤销原仓保护。剩余持仓由账本决定；UNKNOWN 保留原请求身份，不重新 POST。
- 新软件退出使用冻结的 handler/version/config。`risk-trail/v1` 是首个确定性参考管理合同：R 分母按原完整计划预算分配给剩余数量，部分止盈与峰值回撤阈值显式冻结，`max_holding_ms=0` 可禁用时间上限；它不是已证明收益的新策略，更不是自动选择的默认参数。未知 handler 或坏配置不能替代为旧 S6 参数；原生保护继续保留，无保护应急减仓不依赖可用软件退出 handler。
- 一次部分止盈订单只要确有成交，后续取消也不重复卖出同一比例；不足数量步长不生成无效订单。保护失败的应急减仓使用新计划数量步长，不依赖旧 `features.context.directional`。停止开仓、停止策略和管理旧仓严格分开。
- 新现金审计命名空间 `strategy-cash-audit-v1`，结算 source `strategy-settlement-v1`；强制现金依据 v2，不新增旧精度修正特例。最终根锁事务重读原计划、政策、现金、库存和修订号，保留成交、手续费、资金费及钱包等式核验和原子回滚。
- 新复盘存为 `strategy-outcome-v1`，记录计划身份、实际结算、成本、持仓时间与退出证据，不伪造旧 `quality_score`。财务提交以后复盘失败独立重试，不撤销已经结算/释放的资金。完成判断核对原始历史记录及当前结算身份，错误 v1 记录不能悄悄遮住待办；补录采用非权威内存游标轮转，持续失败的记录不独占队首，进程重启从头安全重放。
- 收益复投和恢复探针同时承认经过身份校验的新旧结算；只计当前账本修订号对应的最新结算。结算后追加资金事实会使旧收益暂时失去可复投资格，不能继续用过期结算增加预算。未知来源、错误计划摘要及跨账户数据不成为利润。

边界：仅支持一个完整数量 OPEN 的自然部分成交及多次减仓，不支持同 episode 补仓。新策略 worker、真实新入口授权/基线采集、独立管理进程、完整部署与重启恢复验收仍待接线；看板和旧策略评分统计的新 outcome 投影也需独立适配，不能混入旧评分。本轮没有部署、重启或恢复开仓。隔离模拟交易所验收不等于 Binance Testnet 实际验收，也不等于 72 小时稳定性或收益证明。

### P1 第五轮：显式仅管理进程与停止确认（2026-11-26）

以 `5b8ed7f` 为基线。这是可选择的独立管理入口，不是已经同时启动入场、管理和结算的完整进程组。运行环境未配置此模式，没有部署、重启、恢复开单或调用交易所。

- `V2_CONTROLLER_WORKER_MODE` 默认仍为 `LEGACY`；只有显式设为 `MANAGEMENT_ONLY` 且控制器入场开关关闭才选择新入口。专用 `ManagementProcessConfig` 只校验管理间隔、费率、共享限流模式及写权限，不要求币种列表、TV、JEV 或 quant 参数。它不构造 Redis、ClickHouse、策略、模型、投影、结算或通知组件。
- 每个周期只有订单恢复、原生保护和退出三阶段；不调用包含派发/投影等工作的完整 `runtime.tick()`。普通阶段失败记录后继续尝试保护/退出；账户身份或写权限检查失败则停止本轮，不能为了继续运行而绕过授权。关闭请求在阶段间生效。
- 同时从 `GuardedOpeningSubmit` 和签名请求包装禁止 OPEN 与合约设置写入。减仓、保护和取消仍经过原来的账户/epoch/token guard 及 reduction fence；检查与实际请求使用同一份复制参数，防止等待锁时参数被修改。不会用管理心跳代替开仓许可。
- 管理调度沿用排他的 `v2-pipeline:<scope>` 锁，与旧周期、第二个管理实例互斥；不能直接开启旧循环与新管理循环双写。阶段开始前检查并释放 route guard，真正的交易所修改仍逐次持有 guard，不把 route 行锁覆盖整个管理周期。

### P1 第八轮：限时任务监督、结算轮转与真实进程故障验收

以 `bfb96f6` 为增量基线。只修改 V2 开发工作区；没有部署、重启、恢复交易、运行库写入或交易所请求。新增 `BoundedProcessJob` 是尚未接入控制器的基础设施，不能把它等同于已完成独立结算服务。

- 修复结算扫描固定取首批导致后续单长期轮不到的问题：与复盘补录分开的内存游标在成功、BLOCKED、BUSY 和异常后轮转，仍按原账户、生命周期和闭合成交条件选择。轮转只表示已尝试，不修改财务事实，不释放失败单的资金或风险。已结算单不再入队；重启安全地从头扫描。
- 修复“本批成功即全账户 CLEAR”：一页全部成功后，重新查询同账户当前符合条件的待结算义务；仍有待办就 BLOCKED。若本批已有失败则直接 BLOCKED，不额外全局查询。复查异常不能生成 CLEAR；这是查询时的观测，不授予新的交易权限。
- `BoundedProcessJob` 直接拥有单个 `spawn` 子进程，以绝对时间推进工作截止、合作停止、terminate、kill。迟到轮询不重置宽限期；未证实死亡和回收时保留唯一句柄，拒绝启动替代任务。IPC 只接受固定状态，不传异常详情；任何已开始任务都要求账务核对，包括 COMPLETED。
- 合作停止使用无跨进程锁的共享单字节提示，避免异常子进程把 `Event.set()` 依赖的锁遗留给监督器。子进程可调用 `is_set()/wait()`；该标记不是执行授权或停止证明。监督器必须持续调用 `poll()`；它不是后台自运行的硬实时看门狗，`start()` 的资源创建和进程启动也不受本 API 的非阻塞保证覆盖。目标必须自行创建连接、不得创建后代进程；不声称能监督任意不受约束代码。
- 真实 `spawn` + 临时 PG 验收调用现有 `DirectionalSettlementStage`：资金流水 GET 模拟永久卡死并忽略 SIGTERM 时升级到 kill，随后独立重新获取真实账户锁；账务和风险占用保持未结算，重试可完成。另验证未提交事务被终止后回滚，以及财务已经提交但 IPC 丢失后的重复任务不重复结算。

```text
S3 与 TradingView ──┼─> 统一机会与时点证据 ─> 并行研究和策略评估
可选资金流等证据 ──┘                         │
                                  可选异步模型结果
                                             │
                              候选仲裁与账户统一风险定仓
                                             │
                           不可变交易计划与已有订单执行链
                                             │
                              成交与交易所原生保护
                                             │
                        独立持仓管理与退出 ─> 结算与对照复盘
```

所有研究评估不等于实际执行。一个账户同时只有明确授权的策略组合可以创建意图；研究分支独立保存虚拟组合，不挤占实际资金，也不把不同实验账户收益相加。

### 保留与新增边界

| 边界 | 处理方式 | 交付要求 |
| --- | --- | --- |
| 行情与 TV 入口 | 复用，补机会与数据版本绑定 | TV 是证据及触发来源，不是唯一扫描入口 |
| 策略计算 | 新增统一契约与注册表，包装现有实现 | 纯函数、无网络、无业务写入、有限计算 |
| 模型评估 | 复用现有后台协调及预算机制 | 主交易循环不等待模型，不复活过期机会 |
| 定仓及派发 | 复用，消费统一计划 | 重新检查时效、报价、资金、精度和账户权限 |
| 保护及退出 | 复用状态机，解开策略名称耦合 | 可管理旧版本持仓，不依赖模型可用性 |
| 现金核验与结算 | 复用，统一策略归因 | 包括部分成交、资金费、跨日仓位与未知状态 |
| 分析及控制台 | 扩展现有复盘和策略工作台 | 展示版本、运行模式、实验覆盖和晋升结论 |

初期只增加契约、注册与部署绑定、旧计划解析三类模块。复用现有 PG 状态、证据、任务和 outbox；确需新增列或索引时采用增量迁移，不为每个策略建新表或新微服务。

## 机会发现与数据合同

### 全市场覆盖不等于全市场调用模型

按对应执行环境的可交易目录动态扫描。轻量指标基于闭合 K 线增量计算，各币种公平排队；轮询预算可以限制每批工作量，不能永久只扫描固定前 N 个币。披露每个周期的目录数、有效覆盖、缺页、超时和排除原因。

首轮使用已具备的 15 分钟结构及已闭合 1 小时背景。是否增加 5 分钟快速破位入口是后续独立实验，不在首轮同时改变多个周期。不能把当前未闭合 K 线混入闭合指标，不能承诺捕获所有突发行情。

机会集合在旧 S6/S8 市场软过滤之前分叉，不能只比较原策略已经允许开仓的订单。除事件触发外，按预先登记的闭合周期检查结构，避免原 S3 涨跌幅阈值决定全部研究样本。每日涨跌榜只做事后遗漏诊断，不用于当日机会选择或回填模型输入。

### 分清安全检查和策略观点

| 类别 | 例子 | 缺失或冲突处理 |
| --- | --- | --- |
| 必需执行事实 | 合约可交易、账户状态、最新可执行报价、交易过滤器、保护能力、风险预算 | 停止相关新入场；保留恢复和持仓管理 |
| 策略必需结构 | 连续闭合 K 线、结构位置、有效初始止损 | 当前策略不具备资格，记录原因；不是任务无限重试 |
| 可选增强证据 | TV、OI、资金费变化、top 持仓、现货与链上观察、JEV | 标记未知，采用预先声明的无该特征版本，不伪造中性值或零值 |
| 待检验市场观点 | BTC 大盘方向、量能阈值、追价评分、LLM 意见 | 由策略版本解释，不能自动成为所有策略的全局否决项 |

资金费结算数据的完整性仍是收益评价要求；“可选增强证据”不意味着交易成本可以按零计算。未校准的评分不是胜率。缺少盘口、逐笔或撤单数据时不得从 K 线编造这些特征。

每份证据至少记录来源、市场环境、合约、事件时间、首次可用时间、采集时间、闭合时间、有效期和内容摘要。LIVE 公共行情可以作为独立研究或显式跨环境外部特征；SANDBOX 执行价格、过滤器、成交和资金必须来自 SANDBOX。两者不得混接计算可实现收益。

TV 不覆盖某币、未触发或投递失败应分别计数。本地扫描继续产生机会；同一结构来自 TV 和 S3 时合并来源，不重复下单。TV 与本地数据冲突作为可检验特征处理，不能在未验证新策略时悄悄删除旧版的冲突规则。

## 首轮策略族

这两类是待检验假设，不是已经发现的盈利公式。先复用现有结构实现建立简单基线，新增条件必须有独立对照。

| 策略族 | 目标与触发假设 | 失效条件 | 首轮不做 |
| --- | --- | --- | --- |
| 结构突破与破位延续 | 价格离开此前已知区间，关注区间收缩后的扩张、突破位置和当时成交支持；多空对称 | 回到原结构并满足确认失效，或触发初始硬止损 | 不以已经上涨或下跌很多作为剩余收益预测；不强制慢均线已完全交叉 |
| 趋势回踩与反抽恢复 | 已有方向结构，回撤没有破坏关键位置，随后出现新的恢复确认 | 原趋势结构被破坏，或回撤恢复假设失效 | 不把高 RSI 直接做空、低 RSI 直接做多；不固定等待若干分钟再买 |

量能、主动买卖、OI 和资金费等变量先按数据口径审计，再逐项验证增量；不同时叠加成全部必须通过的门。整体市场方向先作为背景及风险分层变量，局部相对强弱、成本和单币结构可以形成不同判断，但始终受组合风险限制。

同向再进需要新的结构证据；反向开仓需要旧方向失效及新的相反结构，不能由“刚平了多单”直接触发空单。同一机会不因换策略版本、换模型、重启或 TV 重投而再执行。

## 持仓方法与资金约束

### 先比较入场 再比较退出

入口实验使用相同退出规则，避免无法识别改进来源。之后固定入场和风险，单独比较现有退出与结构化持仓管理。

结构化持仓区分试探、趋势确认、趋势剩余仓位和失效退出。状态只能由当时可得的证据推进。初版不自动增加数量；部分止盈后是否保留趋势仓、何时启用移动保护、何时认定停滞，都属于预先冻结的退出版本。

- 初始交易所保护从首次成交开始建立；模型判断不能推迟保护。
- 长趋势版本不因小额浮盈或固定时长自动清空，但仍受结构失效、保护、资金费和资金占用约束。
- 止损不得为了容忍浮亏而放宽；移动保护不得以本根 K 线后出现的高低点回写更早决策。
- 单纯持有更久、赢家事后峰值或某个盈利退出原因，不能证明可实现收益增加。
- 退出始终独立于入场队列、TV 和模型。暂停新开仓不暂停保护、对账和减仓。
- 独立性还包括纯策略计算卡死：管理任务使用独立节奏，策略计算有可强制终止的墙钟预算；账户大锁不能覆盖策略计算或外部等待。缩短锁范围后，订单写入、资金预留与减仓仍必须沿用事务约束和 generation fence，不能简单开两个无协调线程。

### 数量由风险定 杠杆不代表信心

线性 USDT 合约的规划数量采用以下约束关系，实际由现有账户风险模块计算并复核：

```text
本笔计划风险 R = min(参考权益 × 单笔风险比例, 组合剩余计划风险)
风险约束数量 = R / (入场价与失效止损的价差 + 每单位成本和不利成交缓冲)
最终数量 = 按步长向下取整(min(风险约束数量, 保证金可容纳数量, 流动性可容纳数量, 交易所上限))
```

量化后再次校验实际风险、最小下单量、名义价值和交易所过滤器；不足最小量则不下单，不提高风险凑单。止损跳价仍可能超过计划风险，风险比例不是最大实际损失保证。

最多使用 70% 的保守可用资金基数，保留至少 30% 不主动用于新增保证金；这是上限，不是必须用满的目标。余额、权益、已有保证金和在途预留须按账户现有核验口径计算，不能只对“剩余余额再乘 70%”。保留资金不能消除强平风险。

首轮固定风险和杠杆配置；盈利、亏损通过权益基数自然影响后续数量，不根据单日收益追涨风险。后续风险调整单独实验，不与入场更改混在一起。SANDBOX 采样可复用已实现的低风险 profile，但不得借此次迁移放大当前有效限额，亦不擅自改变测试账户已有回撤策略。

## 策略与持仓的统一契约

契约名称为设计接口，具体文件和 schema 在实现阶段确定。

| 契约 | 最少内容 |
| --- | --- |
| OpportunitySnapshot | 稳定机会 ID、市场及产品、标的、闭合周期、结构锚点、来源集合、证据引用、可用时间和 deadline |
| StrategySpec | 策略实例、代码及配置版本、必需数据、支持的计划类型、入口与退出处理器、可选模型配置 |
| EntryCandidate | 候选或拒绝或未知、显式方向、结构假设、失效条件、入场约束、持仓周期、止损建议、理由和证据 |
| TradePlan | 账户作用域、最终数量与杠杆、保护与成本预算、entry 和 exit 版本、机会 ID、配置摘要、部署 generation、期限 |
| ExitDecision | 维持或减仓或退出的意图、原因、数量上限和保护要求；不得产生反向开仓副作用 |

EntryCandidate 不是订单；只有统一仲裁与风险预留成功后才形成可执行计划。金额、数量和价格沿用 Decimal 与十进制字符串，不由模型自由文本直接转换成订单参数。

### 去重与版本分离

当前 consumer 由账户四元组与 producer 构成，不含策略版本。迁移不能简单加入版本来“解决冲突”，否则旧信号可能再次下单。

- 机会身份基于已知市场事件和结构锚点，不以模型或策略版本区别同一交易机会。版本变化若涉及机会算法，必须给出旧新身份兼容规则及重复执行测试。
- 研究可以对同一机会保存多版本评价；执行仍由稳定策略实例、共享机会回执与账户标的占用约束保证唯一。账户与机会的执行权跨策略实例唯一，回执与意图登记同事务；平仓后不释放该机会的已消费记录。另一策略的旧候选不得在前仓结算后接着重开。旧信号与新机会建立兼容映射，不能用换身份绕过去重。
- 首次接受任务时固定部署、证据和配置版本。异步等待、重启与配置发布不重新解释已固定决策。
- 同账户同合约初版继续保持一个活动 episode，不允许多个策略各自把真实净仓位当成自己的独立仓位。候选由统一仲裁选择，失败候选保留原因。
- 配置更新使用现有版本比较与审计，影响新任务；不在每轮就地改 worker 的配置对象。

所有可调决策阈值在各策略自己的版本化 schema 中声明单位、范围和默认值，账户硬风险配置独立维护。工作台支持预览差异、校验、发布和回滚；不能把未经校验的任意 Python 或模型提示当成插件上传执行。历史快照按原 schema 读取，兼容转换显式保留原摘要，禁止拿最新默认值静默补齐历史决策。

部署状态区分研究、灰度、正式执行、仅管理旧仓和退役。初版仲裁按预先冻结的策略预算、优先级与稳定顺序处理，不拿不同策略未经校准的分数直接比大小；候选冲突和资金未分配必须保留记录。

### 持仓跨版本与回滚

开仓时绑定 exit_policy_ref 和初始保护约束。新策略接管新机会，旧持仓继续使用开仓时的退出版本；独立紧急风险处理仍然有效。若确需迁移旧持仓，必须另有显式审计转换，不能静默套用新版本。

新增统一解析器读取旧 directional-admission-v2-1 计划，不批量重写历史证据。管理、保护、现金核验、生命周期、结算和分析均通过同一解析器取值。

回滚先停止新版本新增入场，再回滚部署绑定；未知订单按原身份恢复，已开仓计划继续可被运行代码管理。只有活动仓位、未决订单、保护工作和待结算归属都清零，且历史读取兼容仍存在，才能移除旧执行处理器。

派发许可必须在原子授权点复核当前 entry 状态与部署 generation。切换时，尚未取得提交许可的旧 PREPARED 计划默认终止新增派发，并在证明未提交后按既有协议释放预留；需要排空时必须是显式部署选项。已经取得许可进入 SUBMITTING 或 UNKNOWN 的订单按原身份继续对账，不声称能够撤回已经发出的请求。退出与保护权限不随 entry generation 一起撤销。

## LLM 与 JEV 的职责和降级

模型只回答有证据可核验的问题，例如趋势延续与衰竭的相反解释、哪些新证据能推翻入场假设。数值特征和风险计算由代码完成；不让模型读取凭据、选择交易账户或直接提交订单。

先测一个模型，再测独立反证角色；多角色没有超过单模型就移除额外角色。JEV 作为可替换 provider，与其他模型使用同一合同和成本记录，不享有永久否决权，也不重复设置两道功能相同的审批。

复用后台模型协调与租约。前台提交后立即返回 PENDING，由调度器稍后读取已完成结果；禁止在账户主循环持有租约等待 RPC。模型进程有墙钟期限、队列上限、并发上限和费用预算；仅有 Python 线程超时但请求继续运行不算资源隔离完成。

| 模式或故障 | 确定处理 |
| --- | --- |
| 影子评价 | 模型结果不改变交易；记录覆盖、成本和缺失 |
| 显式规则回退实验 | 模型未及时完成时走冻结的规则分支，单独归因，不能称为模型收益 |
| 依赖模型的新策略 | 无结果则放弃该机会；其他策略和持仓管理继续 |
| 迟到或版本不符 | 记录丢弃原因，不延长原机会期限，不补单 |
| 无 token 或预算耗尽 | 明确计数并降级；不把未评估写成模型通过 |
| 可选数据源失败 | 关闭依赖该数据的增强版本，保留已登记的基本版本；不伪造证据 |

模型失效不阻塞正常流程，不等于资金或订单事实未知时也继续开仓。单个合约坏状态在风险可保守界定时隔离到该标的；账户可用资金或总敞口无法证明时，停止该账户新入场，继续保护与对账并发 DM 告警。

## 数据存储与资源预算

PG 继续作为计划、决策、资金、持仓、任务和结果的业务权威；Redis 只做可重建缓存和限流；ClickHouse 保存行情与分析投影。本地文件只存代码、静态配置、诊断和研究导出，不做运行状态、去重或数据库故障回退。沿用加密密钥管理，不复制上游本地明文 credentials 存储。

共享行情和特征每个周期计算一次，以摘要引用去重；不要为每个角色、每个账户复制完整历史。所有保留机会保存最小决策记录，完整证据采用固定预算和明确覆盖统计；未保留输入的机会不得声称已完整回放。

先测当前资源与峰值流量，再设置研究 CPU、内存、I/O 和数据库并发上限。研究查询只读、有超时；新增任务索引针对未完成任务，完成任务及大 payload 有保留和清理策略。验收必须检查多日数据累积后的查询计划、索引体积、领取耗时和 autovacuum 状态，不能只看空表吞吐。资源受限先减模型覆盖和研究频率，不牺牲保护及退出节奏。

所有事件存真实时间点与来源时区语义，内部排序沿用现有统一时间标准；自然日统计和页面统一 UTC+8。不能把 UTC 数值直接加八小时后当成新的事件时间保存。

## 有期限的验证与淘汰

### 试验顺序

1. A0 冻结当前策略作为对照；A1 使用两个简单确定性策略族。在共同机会、资金预算和同一退出下比较入场。
2. 对通过数据及工程验收的 A1，比较 A2 单模型增强。随后再比较 A3 增加独立反证角色。不同时搜索大量提示词、周期和参数。
3. 固定入场，比较现有退出与趋势持仓版本；不以已经盈利或已经触发特定退出的子集代替全体对照。
4. 策略表现与低风险 Testnet 成交验收分开。LIVE 公共行情研究只能产生模拟结果；SANDBOX 成交验证工程闭环，不能证明实盘可成交价格或盈利。

每组使用相同资金规模与现实资金竞争，不逐币无限补充本金。未平仓仓位保留，并展示按一致价格标记的权益与未实现结果；不能因窗口结束虚构平仓。实际与模拟分开，入场 cohort、最后平仓日结算、账户权益日变化分开。

每个新实验窗口都同时运行冻结对照：A2/A3 与同窗 A1 比较，退出实验对同一批入场分别维护两条退出路径。不得把上一周 A1 与下一周 A2 的收益差直接归因于模型。入口和完整组合比较保留各组独立但等额的虚拟资金；退出的逐笔共同入场实验与考虑资金再利用的组合实验分别报告，不能把前者冒充可执行组合收益。

### 必需证据与衡量方法

预先登记窗口、版本、试验次数、主指标、风险限额、成本假设、样本独立性、失效规则和费用预算。冻结输入要同时证明内容与当时可获得时间；历史模型可能知道后来的行情，LLM 优势必须有前瞻结果支持，不能只靠历史重问。

- 主指标固定为同风险资金下相对同窗对照的成本后净权益差，最大回撤为预登记约束；每单位占用资本收益为辅助指标，不在看结果后挑选最好看的指标。计入手续费、真实或明确模拟的资金费、可达到的成交价格和所有候选的模型费用，包括拒绝、失败和未成交候选的调用成本。
- 解释性比较：早期结构失败、避免的亏损、漏掉的盈利机会、持仓时间与资金占用、趋势剩余仓位贡献、MAE/MFE。峰值只是路径观察，不是可兑现收益。
- 运行比较：全目录覆盖、模型完成率与缺失原因、决策 p95/p99、过期率、重复执行、保护延迟和账户恢复状态。
- 延迟损失通过同一输入的及时与延迟执行路径比较，不能对已经使用延迟成交价格的 PnL 再扣一次所谓等待损失。
- 按日期与市场共同波动分块比较，处理同币重复及同日跨币相关性。胜率、单日总收益、100 笔或 3 折本身不是统计充分性证明。少数暴涨币贡献必须单列。
- 历史行情缺页、退市目录未知、资金费缺失、同根 K 线内止盈止损先后不明时，显示未知或保守情景；不得补成有利成交。回放不能默认限价单触价即成交。

现有 walk_forward 是有限单序列工具，research_acceptance 检查 manifest 形状与门槛，不证明输入断言真实。复用计算组件，但需要补共同机会的组合资金竞争、成本/时间证据验证和可信的结果生成器。

### 决策截止与状态

首轮前瞻窗口从冻结版本和采集通过验收之日算起，固定 14 个 UTC+8 自然日，并预先封顶调用预算；第 7 日只检查安全、覆盖和明显失效，不临时挑选获利参数。第 14 日必须给出以下结论之一：

| 状态 | 行动 |
| --- | --- |
| 不合格 | 成本后无优势、风险不符合预设限额或运行代价过高，停止该实验分支 |
| 证据不足 | 缺失、相关性或行情覆盖使结论不可靠，不晋升；默认结束本轮付费调用，不无限续跑 |
| 值得进一步验证 | 留出窗口有一致增量且工程合格，进入预先限定的 Testnet 灰度；不是实盘盈利证明 |
| 无效实验 | 时间泄漏、错误账务或选择偏差破坏比较，修复证据流程后重新编号，不能沿用原收益结论 |

14 天是资源与决策期限，不保证足够证明长趋势策略。趋势持仓样本不足时可以结束该轮并保留研究结论，下一轮必须提出新的证据目标和预算，不能自动延长。研究通过不自动启用实盘或提高杠杆。

比亏损基线少亏只是相对改进；若成本后仍为负，不能宣称盈利能力达标。风险匹配、主要收益来源的集中程度和不确定区间必须同时报告。

## 实施阶段与交付门槛

| 阶段 | 主要交付 | 完成标准 | 运行交易影响 |
| --- | --- | --- | --- |
| P0 基线与合同 | 冻结版本、全链路身份清单、现有持仓样例、机会及实验合同 | 能解释每个安全门和策略门；已知证据缺口逐项登记 | 无 |
| P1 生命周期解耦 | 统一计划、旧计划解析器、策略注册、不可变部署绑定、管理调度隔离 | 同输入旧策略结果一致；全生命周期可读新旧计划；升级不重复消费；策略卡死不阻塞保护退出 | 隔离 QA，无启用 |
| P2 机会与确定性策略 | 公平扫描、来源融合、两个策略族、组合回放 | 无未来信息；覆盖原策略拒绝者；报价成本与资金竞争可审计；对照完整 | 研究模式 |
| P3 异步模型实验 | 单模型接口、可选独立反证、预算及降级、固定试验清单 | 迟到、无 token、崩溃不拖慢主循环；费用与回退单列；可整个关闭 | 影子模式 |

| P5 闭环灰度与交付 | Testnet 完整演练、控制台、回滚记录、研究判定 | 开仓到结算跑通；多日稳定；运行和收益结论分别报告 | 仅明确启用的 SANDBOX |

P0 到 P4 的代码与隔离 QA 形成一个完整开发交付，不把“接口写完”或“影子进程启动”称为策略升级成功。首轮 14 日研究在所需数据与比较工具就绪后开始；P3/P4 是顺序消融，不强行在同一个窗口修改入口、模型和退出。没有证据支持的阶段可以淘汰，不为完成路线图强行上线。

## QA 矩阵与发布门禁

| 测试层 | 必须覆盖的场景 | 失败时处理 |
| --- | --- | --- |
| 纯函数与因果性 | 未来 K 线不改历史决策、未闭合数据、零与缺失、长短方向、参数越界、确定性重放 | 不进入接线 |
| 计划兼容 | 旧 S6/S8、不同来源、新计划、未知版本、缺失退出 handler、部署中途切换 | 不启用新计划；旧持仓管理继续 |
| 精度与账户风险 | 非十进制步长、极小价、部分成交、最小名义、保证金及并发预留、重复资金费 | 不提交异常订单 |
| 幂等与隔离 | S3/TV 重复、多进程、模型重试、版本升级、账户切换、同标的策略竞争及前仓结算后旧候选重试 | 重复下单或跨账户引用为零容忍失败 |
| 故障恢复 | 提交超时 UNKNOWN、模型宕机、纯策略永久阻塞、保护挂单失败、单币残留、PG/Redis/CH 故障 | 验证按作用域隔离、独立保护节奏、保守风险、DM 告警和恢复，不丢账 |
| 持仓跨版本 | 有仓发布、部分平仓、旧退出继续运行、切换同时派发 PREPARED、已获许可订单、未知订单回滚、退出失败重试 | 不允许旧部署越权新增派发、失去保护或重复减仓 |
| 压测与保留 | 峰值及至少两倍观测峰值的合成负载、多日历史规模、队列饥饿、完成任务增长、清理作业并发 | 不达到冻结的时延及资源预算则不启用 |
| Testnet 闭环 | 自然与受控信号、真实订单回执、原生保护、退出、费用、结算、账户统计、TG | 仅脚本通过不等于自然链路通过；两类分别展示 |

运行 SLO 在 P0 测量后冻结：以信号 deadline、行情新鲜度和保护 SLA 为上界，不能为使压测通过而临时放宽。多日验收至少包含 72 小时非阻塞运行观察和更长历史规模的加速 QA；测试只在隔离数据实例操作，禁止向当前交易库灌压测任务。

发布沿用已有控制器和无持仓核验流程；有仓升级仅在兼容管理演练通过后允许，不通过就等安全窗口。回滚包包含仍在使用的退出处理器。当前实盘账户、密钥和环境不得因实验自动切换。

## 控制台与每日复盘

复用现有首页、账户管理和策略工作台，不另造一个网站。展示当前账户别名、环境、正在执行和仅在研究的策略、entry/exit 版本、风险预算及实验截止日。查看其他账户不改变执行账户。

每日输出固定四项：

1. 实际账务与实验账务各自的收益、成本、敞口和未结算数量。
2. 从目录覆盖、机会发现、策略拒绝、模型缺失、风险拒绝到成交的完整漏斗，未知不记为零。
3. 大行情遗漏及持仓失败的证据、反证和假设状态，不从榜单事后生成买卖理由。
4. 本轮新增了什么证据、哪些假设被推翻、哪些模块应淘汰，以及下一个固定检查点。

TG 群继续以开平仓消息为主，模型预算耗尽、策略故障或订单异常向 DM 发送有去重与恢复通知的告警。长期没有有效模型结果必须可见，不能靠回退掩盖。
