## 程序怎样判定，不接受手工“已核对”参数

入口绑定固定 TESTNET 账户、固定协议 episode/campaign；交易所传输只允许 GET income。
从 PG 读取不可变前置 inventory 和已通过 roundtrip 的最终 inventory，再导入覆盖该区间的流水。
自动校验：

1. 前后账户/环境一致、单向/单资产模式、没有未核对持仓或挂单；快照时间覆盖全部成交。
2. 仅有 OPEN/CLOSE 两个 FILLED 订单；每笔成交归属、唯一身份、成交量与订单数量一致。
3. income 必须完整 FETCHED，记录数匹配；按 incomeType + tradeId 对比每笔手续费及已实现盈亏。
4. 不接受重复身份、未知 tradeId、其他币种、资金费或外部流水；不把手续费/盈亏重复加到账本。
5. 流水合计 = 账本净盈亏 = 前后钱包余额差；任何不一致保留待结算。
6. 最终快照后至少等待 60 秒再拉取；该等待本身不代表完整性，仍须所有上述证据匹配。
7. 自动产生并保存快照摘要、流水摘要/run ID、trade IDs、账本修订号和校验结论，再调用 Ledger。

并发 CLI 使用 PG advisory lock；Ledger 自身锁与唯一键阻止重复结算。
若调用途中失败可重跑，import 按交易所流水身份去重；已结算同修订号直接返回。
