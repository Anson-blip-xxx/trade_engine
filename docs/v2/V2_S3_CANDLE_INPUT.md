# S3 已收盘分钟行情入口

`services/v2_s3_candles.py` 是独立的严格窗口构建器与单次批处理 runner。
接线为原始分钟 K 线→纯窗口计算→纯检测与 PG 生命周期→Redis→源确认。
它不包含 Binance HTTP/WebSocket 客户端，也没有安装常驻服务或打开交易权限。

## 输入契约与有意差异

来源必须显式绑定 BINANCE_FUTURES、SANDBOX/LIVE、1m；每批 1–100 个 symbol，
每个 symbol 恰好 1440 根连续分钟 K 线，最新在前，共享相同 closed_at 边界。
每根字段 t/o/h/l/c/v/tbv 完整，数值只接受有限十进制字符串/整数。
价格必须正且符合 OHLC；成交量非负，主动买入量不超过总量。
拒绝缺口、重复、乱序、进行中 K 线、短历史、错环境和低于输出精度的价格。
规范化原始输入累计最多 8 MB；后续 PG 帧还受自身大小预算约束。

closed_at 是最新分钟开盘时间加 60000，不用扫描时钟制造新鲜度。
新帧还由 publisher 检查相对当前时钟的未来/过期；原帧重试不延长信号期限。
frame_id 来自窗口版本和 closed_at，整个环境内同一边界只有一个完整批次。
不能把同一分钟拆成独立 symbol 批次，也不能重试时更换 symbol 集合或价格。

复用 s3.core 的窗口、EMA、RSI、ATR 计算；无增量 EMA 缓存，重启重算确定性一致。
raw_windows 的 15m/4h 是 15/240 根一分钟线，不是交易所 15m/4h 周期线。
原始 1440 根摘要、窗口版本、范围及来源时间进入市场上下文，并随策略决策冻结。
哪怕改动未参与指标的旧 open 价格，也会触发同身份内容冲突。

旧扫描器混入进行中 K 线，并允许短窗口代替 24h。本入口刻意采用已收盘完整窗口，
属于独立模式而不是宣称逐事件等价。上线前必须比较真实历史回放的信号差异，
评估最长约一分钟延迟及新标的 24 小时预热，不自动切换生产。

## 恢复与监督

runner 的 source.read/ack 必须由上游提供不可变重放和持久确认；runner 不维护
进程内业务游标，更不写本地文件。仅 PG 提交且 Redis 投影成功才确认源批次。
确认丢失可重复处理，生命周期和信号不重复。Redis 失败不确认，同批重试修复。
run_once 返回 IDLE/ACKNOWLEDGED/RETRY，失败只暴露阶段和异常类，不返回原始响应。

当前 source 是注入接口，不是已实现的可靠行情采集服务。还需实现有限网络超时、
补洞/预热、原始行情归档重放、源确认持久机制、毒帧隔离与告警、限频和停止协议。
永久坏帧不能无限阻塞后续行情，但也不能静默丢弃后重标时间；需监督层明确处理。
本入口的时间检查验证自洽性，不等价于认证上游数据真实性。
