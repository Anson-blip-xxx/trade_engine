# V2 行情采集、分块归档与监督闭环

## 本阶段接线

`create_market_pipeline` 组合 PG 限频预算、只读 Binance transport、严格分钟采集器、
ClickHouse 小时分块归档、PG 源投递账本、S3Runtime、Redis 上下文和监督循环。
工厂只绑定显式依赖，不创建网络连接、读取密钥、启动进程或安装服务。
公共客户端默认禁用网络，工厂要求显式传入 `enabled`；禁用网络时既有持久批次的
恢复仍可以执行，不提供任何交易发送口。

`MarketSupervisor.run_once` 先恢复已有批次；未完成队首仍被领取/等待时不采集。
仅无未完成批次时读取服务器时钟，若该收盘边界已登记则跳过 K 线下载。
采集、归档、登记、发布、投影、确认连续接线。`serve` 提供停止事件与有界周期等待，
没有后台自启动。后续已接入 [持久告警队列及隔离补扫](V2_OPERATIONAL_ALERTS.md)：
工厂默认先记录 PG，返回 QUEUED 与独立投递统计；健康轮次也补发旧通知。
直接构造无 alerts 的监督器保留即时 notify 兼容端口。实际 TG 和 PG 外部监控未部署。

## 只读网络安全与时间

仅允许 GET 时间接口和固定 1440 根一分钟 K 线请求，固定 LIVE/SANDBOX 主机，
不接受任意 URL/路径/凭据/签名；无重定向或自动 HTTP 重试。套接字超时 1–10 秒，
响应最多 2 MB，拒绝重复 JSON 字段、非有限常量和错误响应；错误不回传原始正文。
每批 1–20 个显式 symbol，使用服务器时间减收盘等待确定共同边界，校验本地时钟偏差、
元组字段、原始顺序、分钟连续性和收盘时间；不能用本地扫描时刻刷新行情。
采集有单调时钟总预算，检查在请求之间执行，不会强制中断正在执行的系统调用。
DNS、PG、CH、Redis 和告警客户端须由部署方配置有限超时；不能把单个 HTTP 超时
当成整个服务的严格实时保证。历史不足或一处缺口拒绝整批，不补零或混用别的时段。

接口、字段和请求权重已核对官方 [市场数据文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)
及 [环境与限频说明](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)。
限频预算按时间请求权重 1、1440 根请求权重 10 预留；429/418 持久化退避，
Retry-After 在保守上下限内生效，无有效提示时分别等待至少 60 秒/1 天。

## 限流与积压

PG 按显式 egress_scope 记录分钟预算和 blocked_until；预留提交成功才发送网络请求，
失败请求不退额度。相同 scope 的配置必须一致，重启/并发不会清空退避。
PG 时钟回退至旧预算窗口之前时拒绝放行，不把回退误判成新分钟。
同出口 IP 的所有参与实例必须共用 scope；未接入该预算的旧服务、其它应用以及
交易所实际可用额度不受本模块控制，不能声称已经管理全机所有 API 请求。
部署须选择保守预算并持续对照交易所限制，当前未自适应消费响应中的已用权重头。

DurableCandleSource 限制待处理数量，归档前预查，PG 入队锁内再次检查。
并发竞争不能超额入队；同身份重放不消耗新名额。竞争失败可能遗留孤立归档块，
仍须后续引用检查与保留治理。本阶段不删除任何历史归档、回执或运行数据。
入队时固定原有效期和最大行情年龄。恢复未发布帧时发现策略期限配置变化则自动
隔离并审计，不用新配置延长旧场景寿命；已发布帧仍按原记录恢复，不受此项阻断。

## 小时块归档

按 UTC 小时把每个 symbol 的分钟数据分块，块身份包括环境、来源、symbol 和内容。
完整小时块在相邻滑动窗口间复用；首尾部分小时生成新块。批次 manifest 保存原始
头信息和有序块引用。批量读取已有块，只有缺失块插入；写后读回完整再登记 manifest。
还原时逐块、manifest 和最终整批摘要都验证，任何缺块视为暂不可用，明确摘要冲突
才判为损坏。旧整批归档通过兼容读取继续重放，无须迁移或覆盖旧记录。

受控测试中第一帧 24 个完整块，顺延一分钟第二帧仅新增 2 个部分块；不是固定压缩率
承诺。部分小时块、manifest、重复并发插入仍会增长，ReplacingMergeTree 合并不等于
容量保留策略。不得按 TTL 自动删仍被 PG 回执或证据依赖的块；GC/预算仍待实现。

## QA 与剩余门禁

纯测试覆盖块复用/重建/兼容/缺失/损坏、只读路径限制、网络开关、坏响应、权重、
HTTP 退避、时间/历史缺口、采集预算、恢复顺序、停止和告警失败。
临时 PG 验证并发预算、退避重启、数据库失败不联网、入队上限；临时 PG/Redis
贯穿工厂→模拟 HTTP→分块归档替身→S3→源确认，再重启跳过同帧下载。
行情和 CH HTTP 使用 QA 替身，不是实际 Binance/CH 集群在线验收。

尚未部署服务；还需真实沙盒公共行情与 CH 客户端贯穿、窗口行为历史对比、
生产规模性能/容量、归档保留治理、实际告警传输与系统部署/退出演练。
账户风控、真实开仓策略、保护单和全账户自动对账等既有门禁没有因本阶段关闭。
未来窗口算法升级还须保留旧版本重算兼容，或先处理完待投递批次；原始行情归档
不等于自动拥有任意历史算法版本，不能用新算法悄悄替换旧帧的预期摘要。
