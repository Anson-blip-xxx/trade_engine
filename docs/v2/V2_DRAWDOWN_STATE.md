# PG 账户回撤状态与回放上下文

2026-09-21。新增 `v2_core/drawdown.py` 和 `services/v2_drawdown_context.py`。
该检查点迁移余额回撤状态及回放接线，**不是完整账户风险引擎或实盘许可**。
未接通交易所余额采集，未修改旧 Redis 回撤入口，未启用生产策略。

## 状态规则

沿用 `risk/service.py` 的余额口径策略，使用精确 Decimal 比较：

- 距历史余额峰值回撤达到 8%：数量系数 0.5。
- 达到 15%：暂停；新的有效余额观测确认满 4 小时后，恢复系数 0.25。
- 暂停/恢复后相对暂停基准再损失 2%：重新锁定；等待 6 小时后重设基准，
  仍需再等 4 小时才恢复。低于 15% 回撤则清理暂停状态，按当前回撤决定系数。
- 新高抬升峰值。与旧逻辑不同，零余额明确暂停，不允许返回正常系数。

计时只由递增的来源观测时间推进，重复请求或读取当前时间不推进恢复计时。
阈值直接交叉比较，不通过浮点百分比判断边界。

## 存储与并发

使用已有 PG BusinessState / 不可变 state_history，不新增本地或 Redis 业务状态。
键绑定 exchange/account_id/environment/product，固定 namespace 与 policy 版本。
source、currency、max_age_ms 首次记录后固定；配置变化或 tombstone 必须显式处理，
不能通过换配置、删除当前值或重启悄悄重置峰值。

每个账户持有 PG 事务级 advisory lock，再通过 BusinessState CAS 写当前状态和
不可变历史，同一事务提交。重复 observation_id 返回原历史版本；不同内容冲突。
提交成功但响应丢失可幂等恢复；不同身份的同时间或逆序样本拒绝，不覆盖新状态。
晚到样本不会补算峰值，采集器需保证源顺序，并在启动时完成基准/缺口对账。

BalanceObservation 包含 observation_id、非负十进制 balance、observed_at_ms、
evidence_digest。PG 当前时间验证新样本不可过期或未来；同身份审计重放可以过期。
`record()` 返回的是历史审计结果，不能当作当前放行结论。
`current()` 必须再次验证最新状态的新鲜度，缺失、过期、配置冲突均报错。

## 回放接线

DrawdownContext 包装显式的上下文 provider，验证账户/环境/品种和时间，读取 PG
最新有效状态，覆盖 directional.sizing.balance 与 drawdown_factor，使两者来自
同一观测。原始上下文不被修改；新增 drawdown 字段携带 state_id、version、
配置、原始观测及状态，随 StrategyWorker 写入不可变决策证据。

上下文 valid_until_ms 取行情期限和原余额观测期限的最小值，不刷新来源时间。
普通行情 provider 的余额、可用保证金、已用额度、精度、历史统计等仍须由可信
来源提供；此包装器只替换余额与回撤系数，不能证明其余输入已核验。

## 风险与未完成项

- evidence_digest 是调用方提供的证据标识，尚无真实余额响应的归档/摘要核验。
- 这是账户余额回撤，不含未实现盈亏；充值/提现可能改变峰值和回撤，未做资金
  流调整。保证金、净值、外部操作和强平仍需全账户对账。
- `current()` 是读取，不是下单事务的原子许可。下一步须在 OPEN 提交事务内
  校验状态/期限，避免上下文冻结后账户恶化仍被放行。
- 策略仓位上限、信号/品种/平仓冷却、恢复模式换仓及保护单仍未完成。
- 原有回放工厂仍为 REPLAY_ONLY；这里不新增任何下单、重启或部署开关。
