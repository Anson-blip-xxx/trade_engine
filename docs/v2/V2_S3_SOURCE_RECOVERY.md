# S3 持久行情源与恢复

## 存储职责

`ClickHouseCandleArchive` 保存按 SHA-256 寻址的完整原始行情批次。
`DurableCandleSource` 在 PostgreSQL 保存身份、来源时间、原始摘要、S3 预期输入摘要、
期限、租约、尝试次数和终态；不把全量行情塞进 PG。Redis 仍只持有可重建市场上下文。
应用不写本地业务文件，也不依赖进程内消费游标；内存仅持有当前投递的租约令牌。

归档先写入并读回校验，再登记 PG 批次。跨库没有分布式事务：归档成功后 PG 失败
可能留下未被引用的行情对象；可安全重试，不能因此确认源批次。垃圾回收/保留策略
须额外实现，不能删除 PG 未完成投递或历史证据依赖的归档。
当前整批归档 1440 根 K 线，相邻批次有大量重复；内容寻址只消除完全相同批次，
不消除滑动窗口重叠。生产规模前必须评估分块/增量归档、写放大与保留预算，
不能把当前形式直接当作全市场高频采集方案。
ClickHouse 客户端和集群的同步持久性、复制、超时与权限仍是部署门禁；读回可见
不能代替主机断电/多副本灾难恢复验证。

## 投递与恢复

同环境、同帧身份唯一；内容变化拒绝，不刷新原期限。按来源时间取最早 PENDING，
不跳过已领取的队首，以免并发先发布新帧后让旧帧逆序。每次领取使用新租约令牌，
租约过期可接管；旧进程迟到确认失败。每个 source 实例只供一个顺序 runner 使用。

runner 只有 PG 发布和 Redis 投影都完成后才调用 ack；source 还核对已提交 S3 帧的
输入摘要与队列摘要、租约令牌及期限。确认和不可变审计事件在同一 PG 事务。
进程在发布后、确认前崩溃，重启后重放相同帧，不重复产生生命周期或信号。
租约用于投递和确认隔离，不是交易发送许可；实际订单权限仍由独立订单状态机控制。

未发布且过期的批次自动隔离为 EXPIRED_UNPUBLISHED；未发布且被更新的生产批次
超过的帧隔离为 SUPERSEDED_UNPUBLISHED。已发布的旧帧不因过期丢弃，继续恢复投影和确认。
原始摘要、帧摘要或有效输入不匹配隔离为 ARCHIVE_CORRUPT，并留下审计记录。
同身份被其他入口发布不同输入时隔离为 PUBLISHED_INPUT_CONFLICT；若入队前已发现
冲突则直接拒绝登记，避免永久重试阻塞后续帧。
隔离不会恢复为 PENDING，不复活交易信号；重新交易必须来自新的合法观测。

归档缺失/网络异常保持 PENDING，等待租约到期再试。所有隔离均通过 SourceQuarantined
返回给 runner，且能查询 PG 审计；不能将其当作正常空闲。最低告警通道尚待接线。
队首缺失可阻塞后续帧直到恢复或未发布帧过期；已发布且归档永久丢失需要运维恢复，
不能自动丢弃。当前没有实现入口积压限流、归档容量治理、常驻监督或修复操作台。

## QA 与边界

真实临时 PG 验证并发入队/领取、租约接管、迟到确认、已发布过期恢复、未发布隔离、
摘要冲突、确认/入队提交后回执丢失、身份与终态不可变。归档端口用显式 QA 替身注入
故障；ClickHouse local 独立验证真实归档 SQL、重复写入和查询去重。
客户端方法签名按本机安装的 clickhouse-connect 校验，HTTP 客户端与真实 CH 服务之间
的集成、集群崩溃恢复尚未验收，不能宣称完成生产环境三库灾难恢复。
