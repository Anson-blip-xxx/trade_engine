# 方向策略平仓后的现金核验

`services/v2_directional_cash.py` 提供 `DirectionalCashAudit`，仅接受绑定账户的
Binance SANDBOX FUTURES，通过已有分页收入导入器读取真实 income 接口。
不依赖固定 protocol-test episode，不使用本地业务文件，不提供交易所写入能力。

## 实际接线

`audit(episode)` 从 PostgreSQL 获取原始策略决策、订单、成交和账本报表，
在开平仓结束后至少等待 60 秒，重新导入整个成交时间窗的收入流水。
这段等待只是一项保守延迟策略，不是交易所完整性承诺。

核验内容包括：

- 账户、S6/S8 方向策略证据、订单终态、成交数量、开平量相等；
- 逐 trade_id 核对手续费和交易所 realized PnL，再与价格计算的毛盈亏交叉核对；
- 资金费时点必须严格处于已持有仓位期间，与成交同毫秒时拒绝推断归属；
- 拒绝同账户重叠 episode、外部收入、外币费用、重复/缺失流水和现有手工调整；
- 原收入事实幂等导入，导入后重新锁定交易并核对账本快照，变化则拒绝本次结果。

返回的经济分解为 gross_pnl、fees、funding、provisional_net_pnl。
净值为“成交毛盈亏 − 手续费 + 已识别资金费”。资金费仅生成归属候选，尚不写入
交易调整账本；不得再次将已由成交账本计算的手续费/realized PnL 作为现金调整相加。
任何金额不符都拒绝，不自动添加平账补差，也不把此经济分解当作策略因果分析。

## 调度、失败和证据

`run_once()` 可接入 `TradingPipeline(settlement=...)`，扫描本账户已平仓而未结算的
正式方向交易。有界批次和 PG 轮询游标避免单笔异常长期占住队列。
没有已平仓待处理交易才返回 CLEAR。有交易时，即使 CASH_MATCHED，也返回 BLOCKED /
ACCOUNT_SETTLEMENT_REQUIRED。这是过渡期的真实核验接口，不是假装已完成的结算器。

核验过程使用现有账户互斥锁。每次导入前，将该交易的最新 PG 观察状态置为
AUDITING；中途崩溃不会保留旧 CASH_MATCHED 作为最新状态。失败、等待和匹配结果
均记录于 `directional-cash-audit-v1`，错误只保留类别，不保存签名请求或密钥。
重复调用重新抓取相同时间窗，以发现晚到流水；数据导入幂等但观察历史保留新版本。
任何消费者都不得把 CASH_MATCHED 当成最终结算许可，settlement_authorized 始终 false。

## 限制与下一步

此节点没有调用 Ledger.settle，没有写资金费调整/归属，也没有生成最终收益归因。
最终结算仍需使用开仓前已持久化的账户基线与平仓后账户观察，核对钱包余额、
交易所持仓、挂单以及收入完整性，并原子提交资金费分配和结算证明。
账户流水保留期、单次最多 7 天窗口、最多 20 页继承收入导入器限制；超过边界阻断，
不截断后谎称完整。多币种费用、重叠策略仓位和报价舍入差异仍需专门处理。
未部署自动结算服务，未对真实账户执行本次 QA 流水测试。
