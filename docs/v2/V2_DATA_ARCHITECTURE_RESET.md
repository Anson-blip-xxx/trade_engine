# 独立 V2 数据架构基线

2026-09-20 用户授权：V2 按新项目开发，不再保留 main 行为或迁移活动持仓。
本文取代旧路线图中冲突的存储定位、文件恢复副本与兼容性要求。

## 数据权威

- PostgreSQL：交易意图、决策证据、订单/成交、账本、持仓归属和 generation、
  执行租约、审计与事务 outbox 的业务权威。
- Redis：行情窗口、限流与可重建状态投影；不独立授权交易操作。
- ClickHouse：行情历史和衍生分析；交易统计从账本与事件重建。
- 本地文件：仅静态配置、诊断日志和测试产物；禁止业务状态、交易去重、
  账务以及数据库故障时的文件降级。归档不参与运行时业务读取。
- 交易所订单、成交及资金流水是外部事实，持续与 PG 对账。

## A1 契约

请求范围为 exchange/account/environment/product/producer/request_key。
同 key 同内容返回原 intent_id；同 key 不同内容返回 CONFLICT。
内部 UUID 改变不构成新请求；新意图需新 request_key。
数量仅接受十进制字符串，规范化后比较，拒绝 float、非有限值和超精度。
提交响应丢失返回 UNKNOWN；原 key 重试确认，不能换 key 重下。
ACCEPTED 仅表示可靠登记，不表示通过风控或订单成交。
执行及终态转换已实现，但不会自行构造或调用真实交易所 transport。

PG 不可用时不接受新开仓意图。已有仓位的应急处理另行设计，不应因 PG
故障自动撤销交易所已有保护。跨交易所幂等细节须按具体接口验证。

验收覆盖：并发重复、冲突内容、账户隔离、事务回滚、提交响应丢失及原键重试。
真实数据库测试仅运行在一次性隔离实例。
